# 2026-11-10

## Windows tool lookup no longer stops at a malformed PATH entry

On Windows, a PATH entry with an opening quote and no closing quote (such as `"C:\Program Files\Something`) used to hide every directory listed after it, so SQLly could miss pg_dump, mysqldump, sqlcmd and the other command-line tools even though they were installed. That entry is now skipped on its own, and the rest of PATH is still searched. Empty PATH entries are also skipped, so a stray `;;` no longer makes SQLly look for tools in its working directory.
## MySQL and MariaDB connection failures now say why

When a MySQL or MariaDB connection failed, SQLly showed only the raw driver text, such as "invalid peer certificate: UnknownIssuer" or "ERROR 1698", which left a stock local MariaDB install looking impossible to connect to. Each common cause now gets its own message that names the problem and the setting to change: a self-signed or untrusted server certificate (set TLS to Require, or supply the CA file), a certificate for a different host name, an expired certificate, a server with TLS turned off (set TLS to Disable), an account that can only sign in through the local socket (the default for root on Homebrew and package installs; give it a password), a wrong password, no password sent, a host the server does not allow, a database that does not exist or that the account may not use, a full server, nothing listening at that host and port, a host name that cannot be found, and a timeout. An account that uses the ed25519 or parsec sign-in plugin now gets a message saying the plugin is not supported instead of an internal error. The original server or driver detail is kept at the end of every message.

## Missing saved password explains itself

Connecting with a saved connection whose password is missing from the system keyring now explains why and tells you to edit the connection and save it again.

## Connections can be saved without a password

A saved connection can now sign in with an account that has no password, such as the default root account on a local MySQL or MariaDB install. Leave the password blank in the connection editor and save; before, such a connection passed Test but failed every time it was opened. Connections saved blank by an earlier version work again after you open and save them.
