# 2026-10-29

## Redis users without INFO permission still see their databases
A Redis user whose access list denies `INFO`, as narrow users on Amazon ElastiCache often are, could connect but then got a permission error when expanding the server in the explorer or opening the Databases view, because SQLly read the key counts from `INFO keyspace`. SQLly now lists every database anyway and leaves the key counts blank (not zero) when the server will not share them; the explorer shows no count instead of a misleading "empty". The same applies to the single database of a Redis Cluster. Answers [DbGate #1401](https://github.com/dbgate/dbgate/issues/1401) (an ElastiCache user without INFO permission cannot connect).

## Run a Redis command on a chosen cluster node or on every master
On a Redis Cluster connection you can now start a line with SQLLY.ON and a target — masters, replicas, all, or a node's address — to run the command exactly there instead of on the node that owns its key, with no redirects followed, so commands like FLUSHALL, DBSIZE, INFO, CONFIG GET, KEYS and SCAN answer for the nodes you pick and replicas can serve reads. Several nodes answer in one grid with a node and role column, a node that replies with an error gets its own row, read-only connections and the confirmations for writes and destructive commands still apply to whatever follows the prefix, completion suggests the targets, and the Cluster Topology view's new Query on Node button opens a query tab already aimed at the selected node. Answers [Redis Insight #2809](https://github.com/redis/RedisInsight/issues/2809) (run a command on a chosen cluster node or on every master).
## Preconfigure connections from a file or environment variables
SQLly can now start with its connections already set up, which suits Docker, Kubernetes and managed machines. Point an environment variable at a provisioning file, or set one variable per connection holding its URL, including Redis and Valkey Sentinel URLs that list several sentinels, a master name and a database. Any value can pull in an environment variable, and a password written as just a variable reference is read when connecting, so secrets never land in a file or in your saved connections. Provisioned connections show up in the desktop app, the command-line agent and the self-hosted bridge; they are read-only (duplicate one for your own copy), and a broken entry is skipped with a clear warning. Answers [Redis Insight #4737](https://github.com/redis/RedisInsight/issues/4737) (preconfigure Sentinel connections and passwords from environment variables).
## Competitor issue check: Redis Cluster, Sentinel and connections
We checked twelve reports from Redis Insight, DbGate and Chat2DB about reaching Redis Cluster and Sentinel deployments. One was a problem SQLly had too, fixed above in "Redis users without INFO permission still see their databases", and two were features we built today (running commands on chosen cluster nodes, and preconfigured connections with Sentinel URLs). For these, SQLly already had the feature or does not have the bug: [Redis Insight #6537](https://github.com/redis/RedisInsight/issues/6537) (cluster behind locally forwarded SSH ports fails with "Failed to refresh slots cache") — checked, a connection's cluster node map rewrites each node's announced address to the forwarded one, and connections through SSH get a forward per node; [Redis Insight #5393](https://github.com/redis/RedisInsight/issues/5393) (clusters that announce hostnames, such as OCI Cache) — checked, SQLly reads announced hostnames from the cluster's slot and shard replies and dials them as given; [Redis Insight #5379](https://github.com/redis/RedisInsight/issues/5379) (several hosts for one cluster entry) — already have it, list several seed hosts separated by commas and any reachable one is enough; [Redis Insight #3692](https://github.com/redis/RedisInsight/issues/3692) (cluster nodes not rediscovered after they change) — checked, SQLly never saves the node list, reads it fresh on every connection and follows slot moves as they happen; [Redis Insight #3617](https://github.com/redis/RedisInsight/issues/3617) (only one primary node shown) — checked, the Cluster Topology view lists every node the cluster reports; [Redis Insight #3035](https://github.com/redis/RedisInsight/issues/3035) (replicas not shown) — already have it, the Cluster Topology view shows replicas with their master, replication offset, link state and health; [Redis Insight #4806](https://github.com/redis/RedisInsight/issues/4806) (bulk delete does nothing on a Sentinel setup) — checked, SQLly's bulk delete runs on the master Sentinel names, with no web proxy path to get wrong; and [Chat2DB #2674](https://github.com/OtterMind/Chat2DB/issues/2674) (RedisJSON values cannot be opened) — already have it, JSON keys open in the key view and the JSON viewer.
