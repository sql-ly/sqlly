# 2026-10-23

## Column alignment from the header menu

Right-clicking a column header now offers Format ▸ Alignment ▸ Left, Center or Right, which places that column's values within their cells whatever the column's type.

## Completions in the computed-column formula bar

The formula field now suggests as you type. A word lists the Excel functions that start with it and inserts the name with its opening parenthesis. `!` lists the result's columns and inserts a correctly quoted reference. `@` lists the query's variables. Up and Down move through the list, Tab or Enter accepts, Escape closes it, and clicking an entry inserts it.

## Directive help popup no longer follows the pointer around

The "This comment controls how SQLLY formats these results" popup used to appear whenever the pointer was anywhere on a `-- sqlly …` line, covering the lines below while you read or edited them. It now appears only while the pointer is over the `-- sqlly` part at the start of the comment.

## Conditional formatting inputs match the Settings window

The Conditional Formatting dialog's fields now look like the ones in Settings: full-size inputs, dropdown, and color pickers in labeled rows with the same label column, sizes, and text colors. Each value and color now gets its own row (Rule, Number/Text, And, Text color, Fill color, Bold).

## Re-running a pivot query no longer hangs on "Building pivot..."

Running a query that has `-- sqlly view: pivot` a second time could leave the results stuck on "Building pivot..." when the pivot used only rows or only columns. Those queries now open on the result grid's Pivot tab every time, the same as the first run.

## Larger computed-column editor

The formula editor for computed columns is 30% larger: its inputs, text, buttons and spacing are all bigger, so formulas are easier to read and edit.

## Line numbers no longer run into the code

The line-number gutter was a fixed width, so at larger font sizes four-digit line numbers spilled into the text ("3815" overlapping "ELSE"). The gutter now sizes itself from the editor font: it always has room for four digits and widens one digit at a time for longer scripts, up to seven digits (9,999,999 lines). The diagnostic dot and fold arrow move with its right edge.

## Typing stays fast in large scripts

Editing a 0.5 MB data-import script (about 3,900 lines of `INSERT … VALUES`) took around 0.7 seconds per keystroke. Finding the statements behind the gutter's run arrows and the "Run all (N)" count re-scanned the whole script once for every statement in it, so the cost grew with the square of the script's size. The script is now scanned once per edit, and typing in that file takes about 5 ms per keystroke. Opening it got just as much faster. Connections that use the Oracle-style splitter (Oracle, Db2, Teradata, Informix, SAP HANA) had the same problem and get the same fix. Signature help now reads only the statement under the caret instead of the whole script.
