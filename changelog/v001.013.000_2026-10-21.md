# 2026-10-21

## Tenant scoping is off unless you turn it on

Tenant scoping (the missing-tenant-filter warning and the Required run block) is now off by default everywhere: the desktop app, the browser build, the language server, the CLI engine, and older clients that talk to a newer engine. A database only shows tenant warnings or blocks Run after someone explicitly picks Allowed, Warn, or Required for it in Tools ▸ Tenant Scoping. Because earlier versions defaulted to Warn, every tenant-scoping setting saved before this release is cleared on first launch — including databases that had been explicitly set to Warn or Required — so anyone who still wants it has to switch it back on.

## Config files carry a version

`connections.json`, the tenant-scoping file, and every settings file now record the config version they were written with. On startup the app checks each one, applies any changes an older file needs (this release: clearing tenant-scope settings), and rewrites it at the current version so each upgrade step runs exactly once.

## Bold text options in the SQL editor

Keywords, literals (strings, numbers, NULL), and built-in function names are now bold by default. Editor ▸ General has a new Bold text section with a checkbox for each of those, plus system data types, procedures, schemas, user-defined functions, tables and views, and user-defined types. The last five are recognized from the connected database's data model and are off by default.

## IntelliSense matches look like a highlighter

The characters a completion matched are now bold, dark text on a bright neon-yellow fill, so the match is easy to see in every theme instead of only being slightly brighter than the rest of the label.

## Format as you go

Settings ▸ SQL ▸ Formatting has a new Format as you go toggle at the top. When it is on, pressing Enter reformats the statement you are typing and keeps the caret after the same character. When it is off, Format SQL formats on demand from its keyboard shortcut (Alt+Shift+F by default, rebindable under Keybindings). Applying a formatting preset no longer switches the format triggers (as you go, on save, on paste) off.

## Completions follow your SQL formatting settings

Accepting an IntelliSense completion now lays the inserted text out the way Format SQL would for that statement: keyword and function case, identifier case and quoting, JOIN and ON placement, and the rest of the formatting page. For example, with ON clause placement set to On new line, a join completion puts its ON on its own line. Short statements still stay on one line when Keep short queries on one line is on, the same as Format SQL.

## Formatting settings that did nothing now work

Four options on Settings ▸ SQL ▸ Formatting were shown but ignored by the formatter; they now take effect. CTE style Inline puts each CTE body on one line; DML style Compact fits short INSERT/UPDATE/DELETE/MERGE statements on one line and Expanded puts each inserted column, value, and SET assignment on its own line; Multi-line index columns puts each key and INCLUDE column of an index on its own line; and Move trailing comments with expression keeps an end-of-line comment attached to its code when the line is re-broken. Formatting also no longer upper-cases the table name in CREATE INDEX … ON table (…). The Compact and Expanded presets turn the matching options on, so their output changes accordingly.

## IntelliSense Improvement: a new join's ON condition comes first

Right after `INNER JOIN Accounting.FinancialAccountingKey AS fak`, before any ON is typed, the popup used to offer joins to yet more tables, even though the table just added still had no condition. It now offers that table's join conditions only — one per foreign key it shares with any table earlier in the query, nearest first, each written with its ON (`ON fak.AccountId = a.AccountId`) — plus the bare ON keyword for writing the condition by hand. Join conditions after ON now also pair the joined table with every earlier source, not just the one immediately before it (feedback ifb_e275).

## IntelliSense Improvement: after ON, only the full join conditions

Typing ON after a join used to list every column of every table, alphabetically, with the foreign-key conditions filtered out entirely. When foreign keys link the joined table to tables earlier in the query, the popup now offers just those complete conditions — the table being joined written first (`fak.AccountId = a.AccountId`) and the nearest earlier table preferred — with no tables and no loose columns. When no key links them, the columns are still offered for writing the condition by hand (feedback ifb_13aa).

## Improve IntelliSense dialog: copyable query and a visible caret

The query in the Improve IntelliSense dialog is now a read-only text box, so you can select and copy any part of it; its cursor starts where your editor caret was. The "What should it have offered?" box now shows its blinking caret as soon as the dialog opens — it used to take typing with no visible caret.

## Camel-hump word movement

Settings ▸ Editor ▸ General has a new Camel-hump word movement option (off by default). When it is on, Ctrl+Left / Ctrl+Right (Option+Left / Option+Right on macOS), and their Shift selection forms, also stop at each capital letter inside a word — in `SalesOrderLineId` the caret stops at Sales, Order, Line, and Id — and otherwise move between words exactly as before. The setting shows that example right under the checkbox.

## Result name menu and Result Settings dialog

Right-clicking a result's name — its tab in the tabbed layout or its panel header in the stacked layout — now offers Show by Default, Set Number of Rows in Result Set, and Comment Out Result. Show by Default writes a new `-- sqlly focus: <n>` comment so that result's tab is selected (tabbed) or its panel is scrolled into view (stacked) whenever results arrive; Set Number of Rows saves how many rows the result currently shows (a row more than a quarter visible counts) as a `-- sqlly lines <n>:` comment; Comment Out Result puts `--` in front of every line of exactly the statement that produced that result, including a single GO batch or one of several statements on a line. The pencil beside a result's name now opens a Result Settings dialog for the name, the show-by-default choice, the visible row count, and the comment-out action, instead of the inline rename field. Every change is one edit in the query that Ctrl+Z (⌘Z) undoes, and a mistyped `-- sqlly focus:` value is underlined in the editor like other directives.

## Result columns size to their content

When a query runs, each results column now sizes itself to fit both its name and its widest value — growing as rows stream in and shrinking when values are short — instead of starting at a flat 150-pixel minimum sized only from the heading. No column auto-sizes past 30 characters; a longer value or heading is drawn ending in an ellipsis (…) rather than silently cut off at the column edge. The limit is set under Settings ▸ Results ▸ General ▸ Auto-size columns up to, where 0 always sizes columns to their full content. A column you drag keeps its width, and a remembered column layout still wins.

## Row counts set by `lines:` are exact

A `-- sqlly lines:` allocation now sizes the stacked result panel with the grid's real row and header heights (for your density, results font size, and zoom), so `lines: 3` shows exactly three rows instead of about 2.8, and "Set Number of Rows in Result Set" records the true count.

## Format Document in the Edit menu, and a full editor right-click menu

Edit ▸ Format Document formats the whole query with your SQL formatting settings, whatever is selected; it is also listed under Keybindings so you can give it a shortcut. Right-clicking in the SQL editor now always opens a full menu like other code editors: Go to Definition, Run Statement, Cut, Copy, Paste, Select All, Undo, Redo, Find, Replace, Change All Occurrences, Go to Line, Trigger Suggest, Format Document, Format Selection, Toggle Line Comment, Fold All and Unfold All, below any SQL-specific actions for the spot you clicked. Right-clicking inside a selection keeps it selected, so Cut, Copy and Format Selection act on it.

## Tab keeps indenting a selected block

Pressing Tab on a multi-line selection indents it every time, however often you press it, including after Shift+Tab. Previously the autocomplete popup opened at the end of the indented block, and the next Tab accepted a suggestion and replaced the selection. Indenting or outdenting a block no longer opens the popup at all.

## The AI query summary bar is off by default

The AI query summary bar above the results is now opt-in: it is off by default, and while it is off no summaries are requested and the bar is hidden. Turn it on with Settings ▸ Editor ▸ General ▸ Show AI query summary bar, or the same switch under Settings ▸ AI ▸ On device next to the summary model. If you had it on, it stays on.

## Generated scripts end every statement

Scripts that SQLly writes from stored definitions now run back on the server they came from. A SQLite or DuckDB table's stored CREATE TABLE now ends with a semicolon before its index statements, so restoring a SQLite dump with the sqlite3 shell no longer stops at a syntax error; PostgreSQL function and procedure definitions, and MySQL/MariaDB view, routine, and trigger definitions, end with a semicolon too, so a dump or multi-object script with several of them no longer runs them together. MySQL/MariaDB procedures, functions, and triggers in a database dump or a multi-object CREATE script are wrapped in DELIMITER $$ … $$ blocks, so the semicolons inside their bodies no longer cut them short (ERROR 1064) when the script is run with the mysql client or SQLly's Run SQL File.

Answers HeidiSQL [#2591](https://github.com/HeidiSQL/HeidiSQL/issues/2591) (SQLite export script missing statement terminators).

## Run SQL File keeps the comments above each statement

Run SQL File no longer strips the comment lines written above a statement or GO batch before sending it. SQL Server saves a view's, procedure's, function's, or trigger's source from the start of its batch, so a header comment above CREATE VIEW now ends up in the saved object instead of being silently dropped. Blocks that contain nothing but comments are still skipped, consecutive INSERTs that are batched together keep the comment above the first of them, and a final GO at the very end of a file without a line break after it now ends the batch instead of being sent to the server.

Answers DataGrip [DBE-6546](https://youtrack.jetbrains.com/issue/DBE-6546) (comments lost when saving a view in MS SQL).

## Schema Compare deploys changed views and routines correctly

When Schema Compare deploys a changed view, procedure, function, or trigger to SQL Server or PostgreSQL, the script now reads CREATE OR ALTER VIEW (or CREATE OR REPLACE VIEW) instead of CREATE OR ALTER followed straight by the name, which the server rejected as a syntax error. The comments above the definition stay with it, so a view's header comment is deployed too; extra spaces between CREATE and the object keyword are handled; and a CREATE VIEW that only appears inside a procedure's body, a comment, or a string is no longer mistaken for the start of the definition. Repeated deploys and Script as ALTER on SQL Server no longer add two spaces after CREATE in the stored source each time.

Answers DataGrip [DBE-6546](https://youtrack.jetbrains.com/issue/DBE-6546) (comments lost when saving a view in MS SQL) and DBeaver [#42350](https://github.com/dbeaver/dbeaver/issues/42350) (an extra space added between CREATE and PROCEDURE on every save).

## PostgreSQL functional indexes show their expressions

On PostgreSQL, an index's Columns page now lists expression keys such as lower(email) or md5(body::text) instead of leaving them out, so a functional index no longer looks empty or shorter than it is. INCLUDE columns are marked as included and descending keys as descending, instead of every column reading as an ascending key. Script as CREATE for PostgreSQL tables now recreates functional and descending indexes exactly as the server defines them rather than as a broken or shortened column list, and the table structure editor leaves such indexes untouched.

Answers DbGate [#1494](https://github.com/dbgate/dbgate/issues/1494) (functional index missing from a table's structure and SQL).

## Table DDL keeps defaults, keys, and sequence defaults on PostgreSQL and MySQL

The CREATE TABLE that SQLly shows for a PostgreSQL, MySQL, or MariaDB table (in the definition viewer, Script as CREATE from the explorer, and database dumps) now carries every column default, the primary key, foreign keys, and indexes, as the documentation promises. On MySQL and MariaDB it is the server's own table definition, so unsigned types, the storage engine, character set, and MariaDB's DEFAULT nextval(sequence) all survive, minus the live AUTO_INCREMENT counter. On PostgreSQL a column whose default draws from a shared sequence is no longer mistaken for an identity column: only a sequence the column itself owns (a serial) is treated as one, so the default is kept instead of being turned into GENERATED BY DEFAULT AS IDENTITY. The explorer's identity marker follows the same rule.

Answers HeidiSQL [#2586](https://github.com/HeidiSQL/HeidiSQL/issues/2586) (column default from a sequence lost in the generated table script).

## MySQL and MariaDB triggers keep their firing order

When several MySQL or MariaDB triggers share a table, timing, and event, the trigger definition SQLly shows and scripts now says which trigger it follows (FOLLOWS), and a database dump writes those triggers in the order they fire instead of alphabetically. Restoring a dump therefore recreates them in their original order; before, the restored triggers fired in name order, which could reverse what they did. Trigger and table names in the generated definition are now quoted, so names with unusual characters work.

Answers DataGrip [DBE-20597](https://youtrack.jetbrains.com/issue/DBE-20597) (trigger FOLLOWS clause lost from generated DDL).

## A PostgreSQL role named PUBLIC is no longer confused with PUBLIC

On PostgreSQL, the Security dialog's table grants for a role now come straight from each table's access list, matched to that role. A real role named "PUBLIC" no longer shows the privileges that were granted to everyone (the built-in PUBLIC), so unticking one of them no longer produces a revoke that does nothing; it lists only its own grants. Grants made by other users and a table owner's own privileges now show as well. An object's Permissions page likewise counts only your own grants and the built-in PUBLIC's, not those of a role that happens to be called PUBLIC.

Answers DBeaver [#42303](https://github.com/dbeaver/dbeaver/issues/42303) (PUBLIC pseudo-role confused with a role named PUBLIC).

## PostgreSQL scripts and dumps keep object privileges

On PostgreSQL, the definition viewer and Script as CREATE (for one object or several) now end with a Privileges section: the REVOKE statements for access PostgreSQL grants by default but you removed — such as EXECUTE on a function revoked from PUBLIC — and the GRANT statements for access you added, with WITH GRANT OPTION where it applies, the way pg_dump writes them. Running the script now brings tables, views, materialized views, functions, and procedures back with the same privileges instead of quietly handing default access back to everyone. Objects that still have PostgreSQL's default privileges get no section, and a role really named "PUBLIC" is quoted so it is never mistaken for everyone. The section is controlled by Preferences ▸ DDL Navigation ▸ Include privileges in PostgreSQL definitions, which is on by default. Database dumps leave privileges out unless you tick Include privileges (GRANT and REVOKE) in the Export Database as SQL dialog on a PostgreSQL connection, or pass --include-privileges to sqlly-cli dump-database, since the roles they name may not exist where the dump is restored.

Answers DBeaver [#42343](https://github.com/dbeaver/dbeaver/issues/42343) (revoked PUBLIC privileges missing from generated DDL).

## Competitor issue check

We checked these open issues from other SQL clients against SQLly. None of them is a problem SQLly has.

- DBeaver [#42377](https://github.com/dbeaver/dbeaver/issues/42377) (SQL Server INCLUDE columns listed before key columns): checked, not a problem we have. SQLly lists an index's key columns first, in key order, then its INCLUDE columns, in the index properties and in its CREATE INDEX script.
- HeidiSQL [#2589](https://github.com/HeidiSQL/HeidiSQL/issues/2589) (SQLite table script uses MySQL's AUTO_INCREMENT): checked, not a problem we have. On SQLite, SQLly shows the CREATE TABLE text SQLite itself stored, so AUTOINCREMENT comes back exactly as written.
- HeidiSQL [#2577](https://github.com/HeidiSQL/HeidiSQL/issues/2577) (multi-line trigger shows an empty body): checked, not a problem we have. SQLly reads a trigger's timing, event, table and body from the catalog rather than parsing its text, and shows the full body of a multi-line MariaDB trigger on the right table.
- HeidiSQL [#2291](https://github.com/HeidiSQL/HeidiSQL/issues/2291) (changing a PostgreSQL view uses ALTER VIEW … AS): checked, not a problem we have. Script as ALTER on a PostgreSQL view writes CREATE OR REPLACE VIEW, which PostgreSQL accepts.

## PostgreSQL privilege scripting: one-sided ACLs, column grants, and grantors

Scripting PostgreSQL privileges failed with "Privileges unavailable" whenever the object's privileges differed from the defaults in only one direction, which covered the most common cases: a table that only has grants, a function whose PUBLIC EXECUTE was revoked and nothing else, or an object whose privileges were set back to the defaults. Those now script correctly (the last emits nothing). Column-level privileges on tables and views are now included, one GRANT per column and grantee in the same form pg_dump uses, and a privilege granted by a role other than the owner is replayed as that role inside SET SESSION AUTHORIZATION so the recreated privilege records the same grantor. Script as CREATE no longer mistakes a role named in the privileges section for a selected object when ordering a multi-object script. The feature description now claims only what works (tables, views, materialized views, functions, procedures, and column grants); schema, sequence, and type privileges are not scripted.

## Definitions ending in a comment no longer swallow their terminator

A SQLite view or MySQL routine whose stored source ends in a line comment used to get its closing semicolon, or the dump's closing delimiter, appended to that comment line, so the following statement ran into it and a restore failed. The DDL viewer and database dumps now put the terminator on its own line in that case.

## MySQL hash comments are recognised when running and batching scripts

Run SQL File treated a trailing block of hash-style comments in a MySQL or MariaDB script as a statement and sent it to the server, which rejected it as an empty query; INSERT rows beneath such a comment also failed to batch. Both now treat hash comments the same as double-dash comments on those engines.

## Table comments containing AUTO_INCREMENT are left intact

When scripting a MySQL or MariaDB table, removing the live AUTO_INCREMENT counter could also cut the same text out of the table's COMMENT. Only the real table option is removed now.

## PostgreSQL indexes with NULLS ordering or operator classes are scripted exactly

Script as CREATE rewrote indexes using NULLS FIRST/LAST or a non-default operator class as a plain column list, losing those modifiers. They are now replayed verbatim from the server's index definition, as expression and descending indexes already were.

## Format as you go keeps the caret and undoes in one step

Enter's automatic reformat of the statement being typed no longer misplaces the caret when the formatter adds or removes identifier quotes or parentheses, puts the line break after a closing quote rather than inside it, skips any reformat that would change more than layout, and leaves a statement alone when Enter is pressed on an empty line below it or while an input-method composition is open. The reformat and the line break are now a single undo step that restores the exact text and caret, and the formatter settings are cached instead of being read from disk on every Enter and accepted completion.

## Editor context menu shows shortcuts; Format Document in the command palette

The editor's right-click menu now shows the keyboard shortcut beside each command, and Cut and Copy with nothing selected act on the current line (as the shortcuts already did) and are labelled Cut Line and Copy Line instead of being greyed out. Format Document can now be run from the command palette.

## Every settings file carries the config version

Ten settings files that were saved without the config version stamp (gestures, external editor, AI completion, cloud AI, CLI agent, snippets, decision AI, conditional formatting, system notifications, tip of the day) are now stamped and migrated on startup like the rest; files written before the stamp existed still load.

## Camel-hump word movement described accurately

The setting's hint and the keyboard docs now explain that camel-hump movement also stops at the end of a word instead of jumping to the next word's start, rather than claiming movement between words is unchanged.

## IntelliSense Improvement: keywords return after CROSS or NATURAL joins and unresolved join sources

After a CROSS JOIN or NATURAL JOIN table and its alias the popup offered only ON conditions, so typing WH gave an empty list; those joins take no condition and the usual clause keywords are back. When the joined table cannot be resolved (a temp table, CTE, or derived table) the only suggestion was ON and any other prefix emptied the popup; the join keywords now stay as a fallback with ON listed first. Regression tests were added for feedback ifb_e275 (a new join's own ON condition comes first and no other tables are offered) and ifb_13aa (after ON, only the join's full conditions).

## Formatter fixes for keyword-named columns, MERGE assignments, and tables named like index words

A column or table spelled like a keyword behind a qualifier, such as o.type or t.key, was upper-cased and left unquoted as if it were a keyword; it is now formatted as the identifier it is, and quoted when identifier quoting is set to always. Expanded DML style now puts each assignment of a MERGE's WHEN MATCHED THEN UPDATE SET on its own line, as the documentation already described. A table named key or index no longer has its INSERT column list or CREATE TABLE body treated as an index column list, and SQL Server WITH (INDEX (…)) hints are no longer stacked one per line when multi-line index columns is on.

## Cut-off result cells and headers end in an ellipsis

The results grid now draws a trailing ellipsis when a value or column heading is wider than its column, so a cut-off cell always reads as cut off. This comes with the updated grid component the app now ships with.

## Column auto-sizing works on every run of a query

Auto-sized column widths were being saved as the query's remembered column layout, so the second run of the same query restored them, mistook them for widths you had chosen, and stopped sizing columns to the data. Auto widths are no longer remembered: a column you drag keeps its width across runs, every other column is sized to the new values each time, and Reset Column Layout hands all columns back to auto-sizing. Columns are also measured in display cells now, so Chinese, Japanese, Korean, full-width and emoji text gets a column wide enough to read instead of one about half as wide and always cut off with an ellipsis.

## Result-name menu edits are safer and respect the executed selection

Comment Out Results no longer picks the wrong statement when a procedure call produced several result sets next to a statement that returns none; when it cannot tell which statement produced a result it says so instead of guessing. A block comment that starts on a statement's last line and ends on a later line is commented out with the statement, so no stray closing marker is left behind. When only a selection was run, the Show by Default, Set Number of Rows and name edits read and write directives inside that selection rather than elsewhere in the file. The result header only shows a new name, default or row count once the query has actually been edited, so a read-only snapshot tab no longer pretends a change was made.
