# 2026-10-28

## Redis engine auto-detect and a searchable engine picker
The database engine picker now has a search box: type any part of a name, in any case, to filter the list (`memorydb`, `VALK`). A new "Redis-compatible · Auto-detect" entry works out which Redis-protocol product a connection talks to: an Amazon ElastiCache or MemoryDB endpoint is recognised from the host name while you type, which turns TLS on and keeps AWS IAM sign-in available, and any other server is identified as Redis, Valkey, KeyDB or DragonflyDB from its own answer on Test Connection and on first connect, then remembered on the connection so flavor-specific behavior applies. TLS is never guessed by falling back to an unencrypted connection, and choosing a specific engine still overrides detection. Also fixed: pasting a connection URL for a compatible service (such as `valkey://`) now selects the matching engine in the picker.

## Competitor issue check: languages and saved state
We checked eleven long-open issues from Redis Insight, Beekeeper Studio, HeidiSQL and DbGate covering two themes — localization/text handling and saved state surviving upgrades or restarts. One was a problem SQLly had too (saving into a synced folder, fixed in its own entry below) and checking the others led to the hardening in "Unreadable session and connection files are kept and reported"; the rest needed nothing. The saved connections file is written atomically and a connections file that fails to parse is left untouched instead of being wiped, unsaved query text of any size survives an app restart in full (now guarded by a test with a multi-megabyte script), and error messages in any language cross the engine boundary byte-exact (now guarded by a test with a Chinese message). SQLly already ships complete application localization with English and Spanish catalogs of identical coverage, plus a persisted, searchable AI chat history. Checked against [Redis Insight #5810](https://github.com/redis/RedisInsight/issues/5810) (upgrade silently drops configured databases), [Beekeeper Studio #4589](https://github.com/beekeeper-studio/beekeeper-studio/issues/4589) (one unreadable file takes all saved connections with it), [HeidiSQL #2583](https://github.com/HeidiSQL/HeidiSQL/issues/2583) (very large scripts are truncated on restart), [DbGate #1487](https://github.com/dbgate/dbgate/issues/1487) (error messages in Chinese render as garbage), [Redis Insight #6433](https://github.com/redis/RedisInsight/issues/6433) (UI strings still missing from the localization catalog), [Beekeeper Studio #4682](https://github.com/beekeeper-studio/beekeeper-studio/issues/4682) (proposal: build localization infrastructure), and [Beekeeper Studio #4728](https://github.com/beekeeper-studio/beekeeper-studio/issues/4728) (AI chat history lost between sessions).

## Saving into a synced folder no longer looks like an outside edit
Sync clients such as Dropbox, OneDrive and iCloud often re-stamp a file a moment after SQLly saves it, without changing a byte. SQLly compared only the file's timestamp and size against what it last saved, so that re-stamp could raise "changed on disk — reload?" for the user's own save. SQLly now also remembers a fingerprint of the saved contents: when only the timestamp moves and the contents still match, nothing is shown. Real changes made elsewhere still prompt, including ones that leave the file the same size. Answers [HeidiSQL #2390](https://github.com/HeidiSQL/HeidiSQL/issues/2390) (saving into a synced folder immediately prompts "file changed on disk").

## Unreadable session and connection files are kept and reported
If the saved session (open tabs and unsaved query text) could not be read at launch, for example after a crash or after running an older build, SQLly started a fresh session and the next save replaced the old file, losing the scripts in it. The unreadable file is now moved aside under a timestamped name next to the original, and a launch warning says where it is. When the saved connections file cannot be read, SQLly already refused to save over it, but the connection list was simply empty with no explanation; a launch warning now names the problem and says connection changes will not be saved until the file is fixed. The remaining preference files that were written in place now use the same crash-safe write as the rest of the app's data, so an interrupted save can no longer leave a half-written file. Found while checking [HeidiSQL #2583](https://github.com/HeidiSQL/HeidiSQL/issues/2583) (very large scripts truncated on restart), [Beekeeper Studio #4589](https://github.com/beekeeper-studio/beekeeper-studio/issues/4589) (one unreadable file takes all saved connections with it) and [Redis Insight #5810](https://github.com/redis/RedisInsight/issues/5810) (upgrade silently drops configured databases).

## Open Project File asks for a folder instead of scanning your home folder
Choosing Open Project File before any project folder had been opened used to list every `.sql` file under your home folder, which walked into Documents, Downloads, Desktop and other protected folders and made macOS ask for access to each one. It now asks you to pick the project folder first, the same as Open Folder, and only ever scans a folder you chose.

## Epoch dates follow your display time zone
Integer epoch columns formatted as dates always rendered in UTC, whatever display time zone you had chosen, because every epoch override was saved pinned to UTC and no setting could change it. They now follow the global Date display zone unless you pin a zone for that column, and overrides saved with the old default load as "follow global". Answers [Sequel Ace #2078](https://github.com/Sequel-Ace/Sequel-Ace/issues/2078) (BIGINT timestamps as local dates) and [Sequel Ace #2156](https://github.com/Sequel-Ace/Sequel-Ace/issues/2156) (time zone conversion for datetimes).

## Time zones per column and per connection
Date and Epoch column overrides now have their own time zone (follow the global setting, UTC, local, as stored, or any named zone), and new overrides follow your global zone instead of being stuck on UTC. Each connection can also set a Display time zone, so a server that stores local times reads correctly next to one that stores UTC, and a `zone=` option on `-- sqlly format:` lines sets it from the query. Column overrides and directives still win over the connection. Answers [Beekeeper Studio #4793](https://github.com/beekeeper-studio/beekeeper-studio/issues/4793) (configurable time zone for timestamp_with_tz) and [Sequel Ace #2156](https://github.com/Sequel-Ace/Sequel-Ace/issues/2156) (time zone conversion for datetimes).

## Integer timestamps shown as dates
A new "Show integer timestamps as dates" setting under Settings ▸ Results ▸ Date shows integer columns named like `created_at`, `updated_ts` or `event_time` as dates in your display time zone, optionally only when the value falls between 2000 and 2100. It is off by default, your own column overrides win, and copy, edit and export keep the raw number. Answers [Sequel Ace #2078](https://github.com/Sequel-Ace/Sequel-Ace/issues/2078) (view BIGINT timestamps as local dates).

## Your own colors for each data type
"Color cells by data type" now lets you pick a fill and a text color for each kind of value (text, numbers, dates, booleans, unique IDs, binary), with Reset to theme per kind; custom colors apply in light and dark themes, and your conditional-formatting rules still win. Answers [Beekeeper Studio #4792](https://github.com/beekeeper-studio/beekeeper-studio/issues/4792) (data type coloring and customization).

## YAML, Markdown and syntax-colored structured cells
Cells holding YAML or Markdown now open in the value viewer and the Cell Details panel with syntax coloring instead of as one long line: YAML gets the same searchable tree as JSON, Markdown gets a rendered Preview, and recognition is deliberately cautious so an ordinary sentence with a colon stays plain text. With the new "Syntax-color structured values in cells" setting on, JSON and XML values in the results grid itself are colored like code, coloring only the visible part of each cell so large documents scroll as fast as before. Answers [Beekeeper Studio #4795](https://github.com/beekeeper-studio/beekeeper-studio/issues/4795) (highlighting for JSON, XML, Markdown and YAML in the sidebar and table).

## Edit values in the Cell Details panel
The Cell Details panel can now edit the focused value: on an editable result press Edit, change the text in a multi-line editor, and press Apply (Cmd/Ctrl+Enter) to stage it like any other grid change for review and Save. Escape reverts, Set NULL stages a NULL while an empty editor stays an empty string, long values load in full before they can be edited, and when a cell cannot be edited the panel says why. The panel is also easier to find: right-click a cell and choose Edit Cell ▸ Cell Details, or press Cmd+Option+I (Ctrl+Alt+I on Windows and Linux). Answers [Beekeeper Studio #4794](https://github.com/beekeeper-studio/beekeeper-studio/issues/4794) (a values sidebar, not only the JSON view).

## Cell Details and tabs keep up with staged edits
Checking a Beekeeper Studio report turned up three of the same problems in SQLly. Cell Details kept showing the previous row after a re-run, a save or clearing results, and now clears; it showed the committed value of a cell you had edited but not saved, and now shows the staged value, including for new rows; and closing a tab silently threw away staged grid edits when its SQL text was unchanged, which now asks first and marks the tab as having unsaved changes. Transpose also lined values up under the wrong column names while edits were staged, and no longer does. Answers [Beekeeper Studio #4843](https://github.com/beekeeper-studio/beekeeper-studio/issues/4843) (small UX bugs in the table view).

## Hex-looking text stays text
The cell menu guessed "binary" from the text alone, so a text column holding a value such as a `0x…` wallet address was offered View as Hex and binary file actions and lost its text transforms. The binary actions now follow the column's type. Filters and inserts already treated such values as text, and a test now guards that. Answers [DbGate #1469](https://github.com/dbgate/dbgate/issues/1469) (filters reject 0x wallet addresses).

## Schema tree lists objects in one consistent order
Tables, views and other objects were sorted case-insensitively when the tree came from the cache but in the server's order when loaded live, which on case-sensitive MySQL, PostgreSQL and SQLite put every capitalized name ahead of every lowercase one. Both paths now sort case-insensitively, so `booking` sits next to `BookingTimesheet`; columns, indexes and keys keep their meaningful order. Answers [Sequel Ace #2204](https://github.com/Sequel-Ace/Sequel-Ace/issues/2204) (configurable or case-insensitive table sort).

## MySQL COMPRESS() values open, and compressed values can be edited
Values written with MySQL's `COMPRESS()` now decode in the value viewer instead of showing as hex. You can also edit the text inside a compressed value (gzip, zlib, deflate, zstd, LZ4 or MySQL COMPRESS) and SQLly packs it back exactly the way it was stored: in the results grid the edit is staged for review like any other change, and in the Redis key view it goes through the usual reviewed save. A value whose packaging cannot be identified exactly is never re-compressed. Answers [Sequel Ace #2065](https://github.com/Sequel-Ace/Sequel-Ace/issues/2065) (editing compressed BLOBs).

## Decode Protobuf values with your own .proto files
Register .proto files or compiled descriptor sets under Settings ▸ Results ▸ Protobuf Schemas, and the value viewer decodes Protobuf values as the message type you choose, with real field names in the searchable tree instead of field numbers. The message type is remembered for each Redis key across restarts, and a value that does not match falls back to the field-number view with a note saying why. Answers [Redis Insight #4200](https://github.com/redis/RedisInsight/issues/4200) (show protobuf values with custom .proto files).

## Map view and heatmaps
Results with locations now open on a street map: right-click a grid cell and choose Tools ▸ Show on Map…, or switch a geometry value's viewer to Map. Redis GEOSEARCH and GEORADIUS replies, longitude/latitude columns and WKT/WKB shapes are drawn on OpenStreetMap tiles you can pan and zoom, with hover labels, click-to-select-row, clustering, and a Points / Heatmap / Both switch whose heatmap can be weighted by a column and tuned for radius, blur, intensity, opacity and palette. Tiles download only after you agree, are cached on your machine and can be turned off in Settings; without them the map is drawn as a sketch. Answers [Redis Insight #5921](https://github.com/redis/RedisInsight/issues/5921) (visualize GEO and GEOSHAPE results).

## The map directive
A new `-- sqlly map:` directive sets how a result is mapped: which columns, labels and tooltips, colors and sizes, the heatmap, clustering, the street map, the starting view, what a click does, and whether the map opens on its own after each run (`open=auto`, or `-- sqlly view: map`). The map's Options panel edits the same settings and Write to Query saves them into the query's lock block; typos are underlined in the editor and never stop the query.

## Redis memory by key prefix
The Redis Memory Analyzer has a Memory by prefix report showing how much memory and how many keys each key namespace uses, one to three levels deep, with each prefix's share of the sample. You choose which characters split key names, and the connection's key delimiter field now accepts several (for example `:|`) so mixed naming conventions fold into proper folders. Answers [Redis Insight #5373](https://github.com/redis/RedisInsight/issues/5373) (custom or multiple delimiters in Top Namespaces).

## Act on Redis keys selected in a key listing
Run `SQLLY.KEYS <pattern> <limit>` in a query tab, sort or filter the keys by TTL like any result, select the rows you want, and use Tools ▸ Redis Keys to delete them, set their TTL or remove their expiry, with the same confirmation and read-only protection as the bulk actions. Answers [Redis Insight #4062](https://github.com/redis/RedisInsight/issues/4062) (filter and sort keys by column headers such as TTL).

## Filter Keys explains value searches
Typing a JSON value or a search query into Filter Keys no longer just shows an empty list: SQLly explains that the filter matches key names and offers to open an FT.SEARCH over the values in a query tab, or says that a search index is needed. Answers [Redis Insight #5761](https://github.com/redis/RedisInsight/issues/5761) (missing values when searching by value in the key filter).

## PRINT messages and row counts in the Messages pane
SQL Server `PRINT` output and informational `RAISERROR` text (severity 10 or lower) never reached SQLly's Messages pane, because the driver SQLly uses dropped them, and INSERT, UPDATE and DELETE statements reported no affected-row counts. The Messages pane now reads like SQL Server Management Studio: messages appear as the server sent them, in order with your result sets, every statement adds its "(N rows affected)" line (including statements inside stored procedures), changed rows count toward the status bar's run summary, and `SET NOCOUNT ON` hides the counts as it does in SSMS. PostgreSQL `RAISE NOTICE`, `INFO` and `WARNING` messages, which were also dropped, now appear too, with their DETAIL and HINT lines. Answers [DbGate #1224](https://github.com/dbgate/dbgate/issues/1224) (printed query truncated in Messages).

## Filter Apply and Clear are easy to tell apart
In the filter builder, Apply (grid) is now the filled primary button and Clear sits apart at the far left of the footer, so the two can no longer be mistaken for each other. Answers [HeidiSQL #2594](https://github.com/HeidiSQL/HeidiSQL/issues/2594) (filter Apply and Clear too easy to confuse).

## Change column widths without dragging
The column header's Column submenu now has Widen Column and Narrow Column next to Move Column Left/Right; each click changes the width by 40 points, hands the column over from automatic sizing, and is remembered with the rest of the column layout. Answers [Azure Data Studio #26428](https://github.com/microsoft/azuredatastudio/issues/26428) (no single-pointer alternative to dragging column widths).

## Cells with line breaks
Cells containing line breaks now show on one line with a ⏎ marker at each break, instead of crashing development builds or being drawn incorrectly; copy, export and editing keep the real line breaks.

## Competitor issue check: results grids and rich cell values
We checked thirty-one reports from six competitors about cell inspection, structured and binary values, time zones, filtering, sorting, spacing, paging and accessibility. The fixes and new features above answer most of them; for these, SQLly already had the feature or does not have the bug. Checked against [Beekeeper Studio #4799](https://github.com/beekeeper-studio/beekeeper-studio/issues/4799) (local filtering — SQLly already filters resident results with quick filters, a visual builder, typed expressions and saved filters), [Beekeeper Studio #4796](https://github.com/beekeeper-studio/beekeeper-studio/issues/4796) (transpose view — already have Results ▸ Transpose, keeping sort and filters), [DbGate #1576](https://github.com/dbgate/dbgate/issues/1576) (geometry styling — already have consistent point, line and polygon sketches with type, SRID and bounds), [DbGate #1479](https://github.com/dbgate/dbgate/issues/1479) (full content beyond a tooltip — already have a resizable Cell Details panel and full-value viewer that loads large values on demand), [Redis Insight #5745](https://github.com/redis/RedisInsight/issues/5745) (FT.SEARCH not shown as a table — SQLly shows one row per document under both Redis reply protocols), [Sequel Ace #2129](https://github.com/Sequel-Ace/Sequel-Ace/issues/2129) (empty-string indicator — SQLly draws empty strings blank and keeps them distinct from NULL), [Sequel Ace #2191](https://github.com/Sequel-Ace/Sequel-Ace/issues/2191) (row spacing — already have Compact, Normal and Comfortable densities and a separate results font size), [Sequel Ace #2295](https://github.com/Sequel-Ace/Sequel-Ace/issues/2295) (a SELECT showing CREATE TABLE output — checked, SQLly's background metadata reads never share a connection with your query), [HeidiSQL #2290](https://github.com/HeidiSQL/HeidiSQL/issues/2290) (paging changes later limits — checked, table browsing uses a fixed limit and paging never changes it), and [HeidiSQL #2470](https://github.com/HeidiSQL/HeidiSQL/issues/2470) (dotted cell borders on Linux — checked, SQLly draws its own solid, theme-colored grid lines on every platform).
