# 2026-09-30

## Export and import connections with passwords in a credential file

File → Export Credentials… opens a tree of your saved servers with the databases on each one underneath, so you can tick any or all servers and any or all databases under a server, then saves them to a single file with their passwords, shared logins, tunnel profiles, and the colors and icons of the clients, projects, and environments they use. File → Import Connections… reads the same file back — or one written by hand — and every setting the connection editor offers can be carried: engine, host, database, sign-in method, TLS, SSH tunnels, proxies, Kubernetes port-forwards, timeouts, startup SQL, safety toggles, and masking rules. SQLLY checks the whole file first and imports nothing if any entry is wrong, listing every problem at once; imported passwords go straight into the system keychain. Because the file holds passwords in clear text, it is saved readable only by you and should be deleted once imported.

## Run the browser build against real databases through a relay proxy

The browser build of SQLLY can now work against real databases served by a relay proxy: open the app with `?proxy=wss://…&token=…` and every connection the proxy offers appears in the explorer, with queries, the object tree, IntelliSense, plans, and row editing all running through the relay. Passwords stay on the relay host; the browser receives only names, engines, and labels. In this mode the connection list is read-only: adding, duplicating, deleting, and importing connections are disabled, the connection manager's editors are locked, and opening a connection shows it as View Connection.
