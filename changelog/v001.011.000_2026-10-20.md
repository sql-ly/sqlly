# 2026-10-20

## Install updates from inside SQLLY

The update dialog no longer sends you off to download and replace SQLLY by hand. Install downloads the new version for your computer, unpacks and checks it while you keep working (on macOS it must be signed by the same developer as the copy you're running; on Windows, a signed copy only accepts an update from the same publisher), and the button turns into Restart to Update. Restarting saves your workspace as a normal quit does, swaps the new version into place, and opens it again with your tabs and unsaved queries; if any part of the swap fails the old version is put back and SQLLY tells you on its next launch. "Install when idle" downloads straight away and restarts once nothing is running. When SQLLY can't replace itself — a folder you can't write to, a Mac copy still on the disk image or run from macOS's temporary translocated location, or a development build — the dialog says why and keeps the browser download.

## Esc closes function help in one press

Typing into a function call such as `DATEADD(` shows the signature card and, under it, a popup of argument values. Esc used to hide only the signature card, so the popup stayed open until a second Esc. One Esc now closes both.

## IntelliSense Improvement: value lookup re-queries when typing outgrows the sample

The column value popup (Trigger Value Lookup) fetches the first 100 distinct values and then filtered that list locally as you typed, so on a wide column typing `Ton` after `ii.Name like` matched nothing in the sample and the popup fell back to the bare `'%%'` template. A fetch that hits the cap is now treated as a sample: once the typed text is no longer a narrowing of what was fetched, the editor re-queries with the text as a case-insensitive server-side filter (one query in flight at a time, keystrokes while it runs re-check when it lands). Complete result sets keep filtering locally with no extra queries. Covers plain and foreign-key lookups on every engine; the typed text is embedded with its LIKE wildcards neutralised (feedback ifb_2fc6).

## IntelliSense Improvement: temp tables built in the script complete their columns

A table the script itself creates — `SELECT … INTO #temp`, `CREATE TABLE #t (…)`, `CREATE TEMP TABLE … AS SELECT`, or on other engines a `TEMP`/`TEMPORARY` table — now contributes its columns when a later statement reads it: `FROM #efakData d WHERE d.Move` offers `d.MovementReporting` and `d.MovementJurisdictional` the way a catalog table would. The whole script is scanned for those definitions, not just the caret's statement, and `#` names are read as one identifier. Column data types and value lookups on temp tables are not covered yet (feedback ifb_0b20).

## IntelliSense Improvement: a statement's CTEs are offered as FROM and JOIN sources

After `FROM` or `INNER JOIN` the CTEs the current statement declares lead the source list (`journalInventory` above the FK join suggestions and the catalog tables). A CTE is only offered inside the statement that declares it — never in the statements after it — and never before its `WITH` list declares it, while a CTE may still read itself for recursion. Flagging two CTEs declared with the same name as an error is not part of this change (feedback ifb_b360).

## IntelliSense Improvement: DROP TABLE suggests the temp tables the script defines

Typing `drop table if exists #` at the top of a script now offers `#temp` when the script defines or inserts into it further down, with the `#` kept as part of the typed name so accepting the item does not double it. Catalog tables are offered after `DROP TABLE` too. A temp table that another `DROP TABLE` already clears above its definition is left out, while a drop below the definition (end-of-script cleanup) does not hide it. Covers SQL Server `#` tables, `CREATE TEMP|TEMPORARY TABLE` and `SELECT … INTO TEMP` on the other engines, and MySQL's `DROP TEMPORARY TABLE` head (feedback ifb_416b).

## IntelliSense Improvement: join conditions lead with the foreign-key linked columns

After `alias.Column =` in a join condition the in-scope columns a foreign key links to that column — outbound and inbound — come first with an `fk` tag, then columns elsewhere in scope spelled the same, then the rest. A JOIN whose condition is written before its `ON` (`JOIN Shared.TenantLocation AS stl stl.TenantLocationId =`) is now read as a join condition rather than a literal-value slot. Tables not yet in the query cannot be named inside an ON clause, so they are still offered where a new JOIN starts (feedback ifb_e85a).

## Stacked results: grouping, filter and sort controls sit on each result

In the stacked layout the clear-grouping, filter, clear-filters and clear-sort buttons were in the results tab row beside the layout switcher, where they acted on every result set at once. Each stacked result's header now carries its own set, and they act only on that result.

## Directives choose the result layout and the rows each result set gets

Two new `-- sqlly` directives travel with the script. `-- sqlly layout: stacked` (or `tabbed`, or `canvas`) opens the run's results in that layout, for you and for whoever opens the file next; the layout controls still switch it afterwards. In the stacked layout `-- sqlly lines: 8` allots eight rows to every result card and `-- sqlly lines 2: 20` gives the second result set twenty, so a long detail set sits under a short summary without dragging dividers (a dragged divider still wins for that run). Both are honored on any line that holds only the comment; a misspelt layout or a row count outside 1–500 squiggles in the editor, the directive reference window lists them, and `-- sqlly ` now completes `layout:`, `lines:`, and `result:` with their values.
