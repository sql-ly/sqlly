# 2026-11-09

## Protect generated values when editing column descriptions

Changing only the description of a generated stored column no longer rebuilds the table. On MySQL the edit now runs in place as a metadata-only change, verified against MySQL 8.4. MariaDB can only change that description by copying the whole table and regenerating every value, so SQLly now stops with MariaDB's error rather than starting a rebuild you didn't ask for.

Answers [Sequel Ace #2247](https://github.com/Sequel-Ace/Sequel-Ace/issues/2247) (changing a generated column's comment regenerates every value).

## Closing a background tab keeps the right tab active

Closing a tab to the left of the one you're working in used to move focus one tab to the right, along with that tab's connection. The tab you were on now stays active.

Found while checking [Gridex #42](https://github.com/gridex/gridex/issues/42) (query tabs that can't be closed).

## Sync connections, snippets, queries and settings through iCloud

On macOS, SQLly can now keep your saved connections (with their notes, clients, projects, environments, colors, icons and tunnel profiles), snippets and quick actions, SQL Library queries, and appearance, editor, shortcut and formatting settings the same on every Mac, using a folder in your own iCloud Drive. It is off until you tick Sync with iCloud in Settings ▸ Workspace ▸ iCloud Sync. Passwords, SSH key passphrases, tokens and shared logins never leave the Mac they were saved on, so a connection that arrives on another Mac asks for its password the first time you connect.

When two Macs change the same item the most recent change wins, a deleted item stays deleted everywhere, and an edited query that loses is kept beside the incoming one as a conflicted copy. A damaged, half-downloaded or newer-version sync file is skipped without changing anything, and the pane says plainly when the Mac is signed out of iCloud or iCloud Drive is off. Connections, snippets and queries from another Mac appear right away; synced settings take effect the next time SQLly starts. The Mac App Store edition doesn't offer iCloud sync, and Help ▸ Mac App Store Edition now lists that.

Answers [Sequel Ace #2515](https://github.com/Sequel-Ace/Sequel-Ace/issues/2515) (native iCloud sync).

## Clear message when SQL Server only offers old TLS

Connecting to a SQL Server that only offers TLS 1.0 or 1.1 used to fail with an unreadable handshake error. SQLly now says that the server only offers an old TLS version, that SQLly needs TLS 1.2 or newer, and that installing Microsoft's TLS 1.2 update (available for SQL Server 2008 R2, 2012 and 2014) or upgrading the server fixes it. The message also explains that turning off Encrypt does not help, because SQL Server still uses TLS for the login. SQLly still never falls back to TLS 1.0 or 1.1.

Answers [Chat2DB #2928](https://github.com/OtterMind/Chat2DB/issues/2928) (connecting to an old SQL Server fails because it only supports TLS 1.0).

## Notes on each connection

Every saved connection now has an optional Notes box in the connection editor and in Connections & Settings, for things like who owns the server, what it is for, or what to be careful about. Hovering over the server in the explorer shows the notes under the connection details. Notes are included when you export, import or duplicate connections, and connections saved by earlier versions simply start without notes.

Answers [Sequel Ace #2037](https://github.com/Sequel-Ace/Sequel-Ace/issues/2037) (a notes field for each saved connection).

## SSH tunnels that ask for a one-time code

SSH tunnels now work with bastions that want your key (or password) and then a verification code, such as servers set up to require both a key and an authenticator code. When the server asks, SQLly shows its question in a dialog, masks the code as you type, and sends it once without saving it; Cancel stops the connection. A wrong code gets a clear message, and the time you spend finding the code does not count against the connection timeout.

Answers [Sequel Ace #2391](https://github.com/Sequel-Ace/Sequel-Ace/issues/2391) (SSH connections that need a public key plus a one-time password fail).

## Cheaper Inference as a named AI provider

Settings ▸ AI ▸ Cloud ▸ Add profile now lists Cheaper Inference next to OpenRouter and DeepSeek. A new profile comes with the gateway address and the gpt-5.4-mini model already filled in, so you only paste your key; Fetch models lists everything else your key can use.

Answers [Gridex #97](https://github.com/gridex/gridex/issues/97) (Cheaper Inference should be a built-in provider, not a hand-typed custom endpoint).

## Apply to Query carries the grid's sort

Apply to Query in the filter builder now writes the grid's sort into your query as its ORDER BY, along with the filters, so the query you go on editing returns rows in the order you were looking at. Every sorted column comes across in order with its direction, quoted the way your database expects; the query's own ORDER BY is replaced, and any LIMIT, OFFSET, FETCH or FOR UPDATE after it stays put. Sorting alone is enough: you don't need a filter condition to use Apply to Query.

Answers [Sequel Ace #2193](https://github.com/Sequel-Ace/Sequel-Ace/issues/2193) (turn the filtered, sorted table view into an editable SQL query).

## Show binary ids as UUIDs or ULIDs

A binary(16) column holding ids, such as a MySQL or MariaDB binary(16) or varbinary(16) or a SQL Server binary(16), can now be shown as readable ids instead of hex. Right-click the column and choose Format ▸ Set Formatting Override…, then UUID (the usual hyphenated form) or ULID (the 26-character sortable form); the choice is saved with your query and applies to that column only. A value that isn't exactly 16 bytes is still shown as hex. The grid's filters match the id text you see, and a UUID or ULID typed into the filter builder becomes a comparison against the stored bytes when you use Apply to Query, so it finds the row instead of comparing text. UUIDs are read in stored byte order, so ids that SQL Server converted from uniqueidentifier, which reorders the first eight bytes, look different from the original.

Answers [Sequel Ace #2148](https://github.com/Sequel-Ace/Sequel-Ace/issues/2148) (show and filter binary ULIDs the way UUIDs already can be).

## Open SQLLY on a database with a connection URL

You can now start SQLLY with a plain connection URL, such as `open -a SQLLY --args "mysql://user:password@server:3306/database"` on macOS or the URL as the first argument on Windows and Linux, and it connects to that server once you confirm. Any scheme the connection editor's URL box understands works, including mariadb, postgres and postgresql, sqlserver, clickhouse, libsql, redis and valkey. If the server, port, user and database match a connection you already saved, SQLLY uses that one. Otherwise it connects with a temporary connection that shows in the sidebar until you quit and is never saved. When the URL has no password, the confirmation sheet asks for one. The password is used only to connect: it isn't saved, isn't logged, and is removed from the URL before it's passed to a copy of SQLLY that's already running, which then asks for it.

Answers [Gridex #18](https://github.com/gridex/gridex/issues/18) (open the app straight into a connection from a `mysql://` command-line argument).

## Connect through AWS Systems Manager Session Manager

A connection can now reach a database in a private AWS network through AWS Session Manager, with no bastion, SSH key or open inbound port. Tick Connect through AWS Session Manager in the connection editor and enter the EC2 instance to start the session on, plus an optional region, AWS profile and remote host; SQLly starts the session with your installed AWS CLI when you connect and ends it when you disconnect or quit. If the AWS CLI or its Session Manager plugin isn't installed, the editor and the connection error say which one to install, and any other failure shows the AWS CLI's own message. Connections with this setting can be exported and imported like any other.

Answers [Sequel Ace #2470](https://github.com/Sequel-Ace/Sequel-Ace/issues/2470) (connect through an AWS SSM Session Manager tunnel).

## AWS IAM sign-in works through your own DNS name for RDS

A PostgreSQL or MySQL connection that uses AWS IAM can now name the database by a company alias such as db.example.com instead of its Amazon address. SQLly follows the alias to the RDS or Aurora endpoint behind it and signs the sign-in token for that endpoint, which is the only name RDS accepts, while still connecting to the host you typed. If the alias can't be looked up, SQLly signs for the typed name as before.

Answers [Sequel Ace #2423](https://github.com/Sequel-Ace/Sequel-Ace/issues/2423) (IAM authentication fails when the host is a CNAME to the RDS endpoint).

## Run SQL File runs mysqldump files with routines, triggers and views

Run SQL File used to cut mysqldump's `DELIMITER ;;` lines in half, so procedures, functions and triggers in a dump failed, and it skipped the view and trigger statements mysqldump writes inside `/*!…*/` version comments as if they were plain comments. Both now run the way the mysql client runs them.

Found while building [Sequel Ace #2080](https://github.com/Sequel-Ace/Sequel-Ace/issues/2080) (importing a dump whose DEFINER accounts don't exist).

## Extra mysqldump options and DEFINER-free dumps

The native mysqldump dump now takes extra options you type yourself, such as `--skip-comments` or `--column-statistics=0`, each passed to mysqldump as its own argument and never through a shell. Options that would change where the dump goes, which account it signs in with or which server it reaches are refused with a reason. A new Remove DEFINER clauses checkbox strips the owning accounts from views, routines, triggers and events in the finished file, so it restores on a server that doesn't have those accounts; table data that merely mentions DEFINER is left alone. Both settings are kept in dump schedules and in the copied command line (`--mysqldump-option`, `--strip-definer`).

Answers [Sequel Ace #2203](https://github.com/Sequel-Ace/Sequel-Ace/issues/2203) (passing extra flags to mysqldump) and [Sequel Ace #2080](https://github.com/Sequel-Ace/Sequel-Ace/issues/2080) (DEFINER accounts that don't exist on the target server).

## Remove or remap DEFINER in Run SQL File

On MySQL and MariaDB connections, Run SQL File has a DEFINER setting: keep the clauses as written, remove them, or change them to CURRENT_USER before each statement runs. The review page says how many DEFINER clauses the file has and what will happen to them, and string data in the file is never touched. Checked against a real mysqldump 8.4 file imported by an account without the SUPER or SET_ANY_DEFINER privilege: the file as written fails, and both the removed and the CURRENT_USER versions import with every view, routine, trigger and event intact. The command-line tool takes the same choice as `run-file --definer strip|current-user`.

Answers [Sequel Ace #2080](https://github.com/Sequel-Ace/Sequel-Ace/issues/2080) (importing a dump whose DEFINER accounts don't exist).

## Named groups of pinned objects

Pinned tables, views, routines and databases can now be sorted into named groups, such as one per feature you're working on, shown as folders at the top of their server. Right-click an object and choose Pin to Group to put it in an existing group or name a new one; a group folder can be renamed or deleted, and objects inside a group can be reordered or moved to another group. Deleting a group keeps its objects pinned. Pins you made before this release load unchanged, outside any group, and still rise to the top of their own folder.

Answers [Sequel Ace #2256](https://github.com/Sequel-Ace/Sequel-Ace/issues/2256) (groups of pinned tables, one set per task).

## A larger editor for long structure fields

In Edit Structure, an expand button beside a column's Default and Description, beside the type of an ENUM or SET column, and beside the table's Description opens a multi-line editor, and Apply writes the text back into the field. Descriptions keep their line breaks, and ENUM and SET values are listed one per line so you can add, remove or reorder them without quoting each one; the change preview and generated script update as usual.

Answers [Sequel Ace #2396](https://github.com/Sequel-Ace/Sequel-Ace/issues/2396) (popup editors for long defaults, comments and ENUM lists).

## Find in the definition viewer

The read-only definition viewer has a find bar: click Find in its header or press Cmd+F (Ctrl+F on Windows and Linux), type, and every match is highlighted with the current one marked and a running count. Enter and the down arrow go to the next match, Shift+Enter and the up arrow to the previous one, each scrolled into view, and Escape closes the bar.

Answers [Chat2DB #2748](https://github.com/OtterMind/Chat2DB/issues/2748) (searching inside a table's DDL); Go to Column in the results grid still selects the column without scrolling to it.
