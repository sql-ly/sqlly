# 2026-11-10

## Formatter keeps quotes on reserved words like [User]
The SQL formatter's "Remove unnecessary quotes" and "Quote only when required" settings could strip the brackets off names such as `Shared.[User]`, leaving `Shared.User`, which SQL Server rejects because `USER` is a reserved word. The formatter now checks the engine's full reserved-word list before removing quotes, so `[User]`, `[Order]` and `"group"` keep them under every setting. "Quote only when required" now also adds quotes where a reserved word is used as part of a qualified name (`Shared.User` becomes `Shared.[User]`), while a bare `USER` is left alone because it is the current-user function. "Always quote" no longer quotes bare `USER`/`CURRENT_USER`, and on PostgreSQL and Oracle it quotes with the case the engine would have used (`Orders` becomes `"orders"`, not `"Orders"`, which is a different table).

## Query parameters: `:name`, `?` and `$1` placeholders now ask for values
Writing `WHERE id = :id` in a query used to send `:id` to the server as written, so MariaDB, MySQL and others failed with a syntax error near `:id`, and SQLly only asked for values when you declared them with a `-- sqlly param:` comment ([Chat2DB #2944](https://github.com/OtterMind/Chat2DB/issues/2944), reported to us by its author). Named `:name`, positional `?` (and SQLite's `?3`), PostgreSQL / DuckDB `$1`, and on SQL Server any `@name` the script doesn't `DECLARE` (or assign, or define as a procedure parameter) now each get an input in the Parameters strip above the results on every engine, and Run fills in what you type, properly escaped, without touching your script; numbers, true/false and NULL are used as typed, anything else is text, and quotes (`'42'`) force text. Only the statement you run needs its values, a missing one blocks the run and focuses its field, `-- sqlly param: :since date` gives a placeholder a type and default, Explain and query plans use the same values, and placeholder lookalikes in strings, comments, function bodies, `::` casts, array slices, labels and variables are never mistaken for parameters. Settings ▸ Editor ▸ General ▸ Query parameters turns detection off.

## Formatter no longer splits `:name` and `?` placeholders
On MySQL, MariaDB and SQL Server the formatter turned `id=:id` into `id =: id`, which no longer runs, and on SQL Server and Oracle a `?` stopped the query from being formatted at all. Placeholders now stay whole on every dialect, `x=?` formats as `x = ?` under Auto Detect, and PostgreSQL's `?|` / `?&` jsonb operators are still read as operators.
