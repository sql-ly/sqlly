# 2026-11-17

## IntelliSense Improvement: foreign-key join suggestions use your alias rule

Join suggestions built from foreign keys now name the joined table with the alias rule in Preferences ▸ Editor, the same rule plain table completions already used. With "capital letters, lowercased", typing `INNER JOIN` after `Accounting.Journal AS j` offers `Accounting.JournalLine jl ON jl.JournalId = j.JournalId` instead of `j2`, and `Shared.TenantUser` becomes `tu` instead of `t`. Taken aliases still get a number (`jl2`). The first-letter rule keeps the old aliases, and "do not suggest" also uses first letters for joins because the ON clause needs an alias. This fixes ifb_6da8 (regression test `journal_line_join_is_aliased_jl_under_the_capital_letters_rule`).

## PostgreSQL partitioned tables keep their partitions in DDL

The DDL view and Script as CREATE now script a PostgreSQL partitioned table with its `PARTITION BY` clause and a `CREATE TABLE … PARTITION OF` statement for every partition below it, including sub-partitioned and default partitions. Before, the script quietly produced an ordinary table with no partition key and no partitions. Opening the DDL of a single partition now shows its table followed by `ALTER TABLE … ATTACH PARTITION`, so it goes back under its parent. When a script covers both a partitioned table and its partitions, each partition is created once. A partition that is a foreign table is left out with a warning. Checked against a live PostgreSQL 17 server: both scripts rebuild the same partition tree and indexes.

Answers competitor issue: CloudBeaver [#4913](https://github.com/dbeaver/cloudbeaver/issues/4913) (the full DDL of a partitioned table doesn't include its partitions).

## SSH tunnel "No route to host" points at macOS Local Network access

When an SSH tunnel or proxy hop to a host on your local network fails with "No route to host" on macOS, the error now says macOS may be blocking SQLLY and where to allow it (System Settings ▸ Privacy & Security ▸ Local Network). Direct PostgreSQL, MySQL and SQL Server connections already showed this hint; tunnelled ones showed only the bare error.

Answers competitor issue: Sequel Ace [#2324](https://github.com/Sequel-Ace/Sequel-Ace/issues/2324) (SSH tunnel fails with "no route to host" for a host that plain ssh reaches).

## SQL Agent job steps choose what happens on success and failure

The SQL Agent job editor has On success and On failure choices for the step you are adding or editing: go to the next step, quit the job reporting success, quit the job reporting failure, or go to a specific step by its ID. The reviewed script passes them to SQL Server, and "Keep current / default" leaves an edited step's existing setting alone (a new step gets SQL Server's default), so a "go to step" flow set elsewhere is never reset to "next step" by accident. The editor refuses a missing or invalid target step and a step that would go to itself before you script it.

Answers competitor issue: Azure Data Studio [#26104](https://github.com/microsoft/azuredatastudio/issues/26104) (the job step editor only offers the default next-step choices).

## WarehousePG connections

WarehousePG, the open-source Greenplum fork, is now a connection type in the PostgreSQL-compatible group, on port 5432 with every PostgreSQL tool available apart from the designers. Its table DDL and Script as CREATE keep each table's DISTRIBUTED BY, DISTRIBUTED RANDOMLY or DISTRIBUTED REPLICATED clause after the column list (and after PARTITION BY), so a scripted table lands on the same segments layout instead of the server's default distribution; if the distribution can't be read, the script says so in a warning. Not yet tested against a live WarehousePG server.

Answers competitor issue: CloudBeaver [#4875](https://github.com/dbeaver/cloudbeaver/issues/4875) (add WarehousePG as a database type).

## Copy and Cut work in the browser version over plain HTTP

Browsers only offer their clipboard API on secure pages (HTTPS or localhost), so the browser version of SQLly, the in-tab preview and SQLly Embedded pages, had no working Copy or Cut when it was served over plain HTTP, for example an Embedded install on a LAN address without a TLS certificate. Copy and Cut in the editor, grid and inputs now fall back to the browser's older copy command when the clipboard API is missing or refuses the write. Paste already worked there through the browser's own paste, and still does. Pages served over HTTPS are unchanged.

Answers [Chat2DB #2361](https://github.com/OtterMind/Chat2DB/issues/2361) (Copy and Cut fail in the web build when served over plain HTTP).

## Redis and ClickHouse connections no longer demand a user name

The connection editor refused to save any user-and-password connection with a blank user name, so a Redis, Valkey, KeyDB, DragonflyDB, ElastiCache or MemoryDB server with no AUTH set up could only be saved by typing `default`. Those engines, and ClickHouse, now accept a blank user: Redis connects as its default user and sends no AUTH at all when the password is blank too, and ClickHouse signs in as its `default` user. The user field says so in its placeholder. SQL Server, PostgreSQL, MySQL, Oracle and the other engines whose protocol needs a login still ask for one.

Answers [TablePlus-Windows #826](https://github.com/TablePlus/TablePlus-Windows/issues/826) (connecting to a server that needs no user name or password).

## Toggle Block Comment in the SQL editor

The editor can now wrap the selected SQL in a /* */ block comment, or take the markers back off, with Cmd+Shift+/ on macOS or Ctrl+Shift+/ on Windows and Linux. With nothing selected it wraps the current line, an empty line gets an empty comment with the caret inside, and a comment that already holds other comments unwraps cleanly. Each toggle is a single Undo step, the command sits in the Edit menu next to the line-comment entries, and its shortcut can be changed in Settings > Keyboard Shortcuts.

Answers [Chat2DB #2339](https://github.com/OtterMind/Chat2DB/issues/2339) (asked for rebindable line and block comment toggles).


## Recent filters in the Filter rows dialog

Every filter expression you apply in the Filter rows dialog is now remembered for that table, newest first and without duplicates, and a Recent filters dropdown beside the Expression field applies one again with a single click. The list is saved to disk, so it is still there after you restart SQLLY. Recents are kept per table (and connection) rather than globally because an expression names that table's columns. Settings ▸ Results ▸ General has a new Filtering section with Remember recent filters, how many to keep per table (10 by default), and Clear recent filters.

Answers [HeidiSQL #2664](https://github.com/HeidiSQL/HeidiSQL/issues/2664) (the recent filters list should survive a restart).

## Text and ENUM column defaults are quoted in the structure editor

Typing a plain value such as `a` as the default of a text, ENUM or SET column used to produce `DEFAULT a`, which the server rejects. The structure editor's script now writes it as a string literal (`DEFAULT 'a'`, escaping any quotes inside) on MySQL, MariaDB, PostgreSQL, SQL Server, SQLite and the other supported engines, and typing the value a column already has no longer shows up as a change. Expressions are left exactly as typed: quoted values, numbers, `NULL`, `CURRENT_TIMESTAMP` and similar keywords, function calls and parenthesised expressions.

Answers [Beekeeper Studio #5059](https://github.com/beekeeper-studio/beekeeper-studio/issues/5059) (an ENUM column's default was written unquoted, so the change failed).

## Column lists load on MySQL before 5.7 and MariaDB before 10.2

The table's column list in the object browser and object editor, the column properties page and the structure editor all asked the server for a generated-column field that MySQL only added in 5.7 and MariaDB in 10.2, so on older servers they failed with an unknown-column error and showed no columns. Generated columns are now recognised from information every version reports, and the structure editor reads columns without that field when the server does not have it.

Answers [Sequel Ace #2395](https://github.com/Sequel-Ace/Sequel-Ace/issues/2395) (a table's structure view broke on MySQL 5.1).

## Edit JSON pretty-printed, save it minified

A new setting, Settings ▸ Results ▸ General ▸ "Save edited JSON as", chooses how a JSON value you edit is written back: Minified, Pretty-printed, or Keep as typed (the default, which behaves exactly as before). With Minified or Pretty-printed, the Cell Details editor opens a JSON column's value indented for editing, and applying the edit there or saving it from the row editor stores it compact or neatly indented. Key order, numbers and string text are kept exactly as written, and anything that is not valid JSON is saved just as you typed it.

Answers [DbGate #1477](https://github.com/dbgate/dbgate/issues/1477) (edit JSON pretty-printed but store it minified).

## Table partitions no longer flood table suggestions

On PostgreSQL, every child partition of a partitioned table used to show up as its own table when completing a FROM or JOIN, so a table split into daily partitions buried everything else under hundreds of near-identical names. Table suggestions now leave child partitions out while an ordinary table or view matches what you typed, and offer them once only partitions match, so typing the start of a partition's name (`events_2024_`) still finds it. The schema explorer still lists every partition. Partitions that are partitioned again are hidden the same way, while tables that only inherit from another table (classic inheritance) stay ordinary tables.

Answers [DBeaver #42745](https://github.com/dbeaver/dbeaver/issues/42745) (hide child partitions from table autocomplete unless nothing else matches).
## Aliases after a MySQL partition list complete again

In a MySQL query that reads chosen partitions, such as `SELECT a. FROM orders PARTITION (p0) a`, typing the alias and a dot offered no columns, because the word PARTITION was taken for the table's alias and the real alias after the list was never seen. The alias after a partition list now belongs to the table, with or without AS, so `a.` offers the table's columns and the query's other checks know what `a` refers to.

Answers [DbGate #1500](https://github.com/dbgate/dbgate/issues/1500) (alias after PARTITION (...) breaks column autocomplete).

## Sign in to PostgreSQL 18 with OAuth

PostgreSQL connections can now use PostgreSQL 18's OAuth sign-in with an OpenID Connect provider (Okta, Keycloak, Microsoft Entra, Google and the like) instead of a database password. Choose "OAuth (PostgreSQL 18+)" in the connection editor, enter the database user and the client ID your provider issued (the issuer URL and scope are optional and are taken from the server when left blank; a client secret is optional too and stays in your system keychain), then Test or Connect: SQLLY opens the provider's page in your browser and shows the one-time code to enter there, and the tokens it gets back are kept in the keychain and renewed quietly, so later connects need no browser. If you already have a token, choose "OAuth token" and paste it instead. OAuth connections always use TLS, and SQLLY refuses to sign in when the server names a different provider than the one the connection is set to. Errors say plainly whether the server does not offer OAuth for that user and database, the token was rejected, the provider could not be reached or read, you declined the sign-in, or the code expired. The command-line tool and engine accept `--auth pg-oauth` with `--access-token` (or `SQLLY_PG_OAUTH_TOKEN`).

Answers [Postico #906](https://github.com/jakob/Postico/issues/906) (OIDC / OAuth sign-in to PostgreSQL 18).
