# 2026-10-06

## Queries no longer run in the wrong database after activating a server in the explorer

The database picker in the query bar could show one database while queries
ran in the login's default one, usually `master`. Two things lined up to cause
it. Pressing Enter or double-clicking a server row in the explorer re-adopted
the saved connection as-is, and since a saved connection usually names no
database, that quietly dropped the database you had picked. At the same time
the picker kept painting the previous selection whenever its option list was
replaced, so nothing on screen changed. Activating the server you are already
connected to now keeps the chosen database and goes through the normal
connect path, and the picker clears or re-applies its selection every time
its options change, so what it shows is what the next query runs against.

## IntelliSense feedback reports include stored procedure parameters

A feedback report used to carry only the bare names of the stored procedures in scope, so an `EXEC` completion problem could not be reproduced from it. Reports now include each procedure's schema and full parameter list — name, data type, and whether it is an OUTPUT parameter — so each procedure reads as a signature, e.g. `dbo.GetOrder(@id int, @total decimal(10,2) OUTPUT)`.
