# 2026-11-08

## Dependency refresh: newest GPUI, keyring 4, DuckDB 2.0
The app now builds on the newest UI framework releases (gpui 0.3.11 and gpui-component 0.9.0) and the results grid crate moves to 10.0.0 to match. Custom keyboard shortcuts from keybindings.json now load through the framework's runtime keystroke parser, which this release requires for shortcuts built at runtime. The macOS window backend is re-vendored with the Mac App Store patch reapplied. Saved passwords move to keyring 4 and stay in the same macOS Keychain, Windows Credential Manager and Secret Service entries, so existing credentials keep working. DuckDB moves to 2.0 (the Windows build now downloads DuckDB's new shared-library archive), and SQLite (rusqlite 0.41), SSH tunnels (russh 0.65), Redis, the MCP server, YAML, Excel import and native file dialogs are on their latest releases too.

## Typed text always shows up on macOS
The newer UI framework drives macOS repaints through Metal's display link. In testing on macOS 26, that occasionally skipped the repaint after an edit, so typed text stayed invisible until the window was resized or reactivated. SQLLY now paces frames with the display link the previous release used. Setting `SQLLY_METAL_DISPLAY_LINK=1` switches back.

## DuckDB query plans after the DuckDB 2.0 move
DuckDB 2.0 reshaped its EXPLAIN ANALYZE output, so actual plans for DuckDB connections showed a single empty node. The plan pane reads the new layout (and still the old one), drops DuckDB's internal wrapper steps, and shows actual row counts and per-operator time again.

## Browser build: SQLite and ⌘ shortcuts
The browser preview links again after the SQLite library update, which now needs the page to supply its clock and random-number hooks. ⌘C in the results grid and ⌘-click in the schema tree keep working in a Mac browser now that the UI framework reports the host OS at runtime.
