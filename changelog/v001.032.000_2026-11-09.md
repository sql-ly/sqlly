# 2026-11-09

## SQL Server plan findings read real plans correctly

The plan pane now reads SQL Server plans as real XML instead of scanning the text, which fixes several findings on plans captured from a server. Missing-index suggestions and "implicit conversion blocks a seek" warnings, which SQL Server records on the statement rather than an operator, were never shown before; they now appear on the scan they describe. A scan's or lookup's warning no longer repeats on every operator above it, key lookups are recognized in the form SQL Server actually writes them, parallel operators add up the rows of every thread, and the inner side of a nested loop no longer reports a false row-estimate miss because its estimate is now compared across all of its executions. Index scans that read a whole index to apply a filter are flagged like table scans, row goals and table or index spools get their findings, excessive memory grants are reported, and a plan cut off in the middle (as the SSMS grid does to large XML) is reported as incomplete instead of being half read. On MySQL, reading back the server's own temporary table no longer counts as a full table scan.

## Open Plan and Paste Plan accept more formats

Opening or pasting a plan now also reads Oracle's DBMS_XPLAN output (including ALLSTATS LAST with actual rows), the sqlite3 shell's EXPLAIN QUERY PLAN tree, DuckDB 2.0's EXPLAIN ANALYZE JSON, and output copied straight from psql or the mysql client with their borders, headers and line continuations still attached.

## Format SQL no longer breaks JSON operators, prefixed literals or numbered parameters

Format SQL and Minify SQL could change what a query does by putting a space inside syntax the editor's lexer split in two: MySQL and SQLite `->>` became `-> >`, MySQL `<=>` became `<= >`, SQLite `==` became `= =`, `x'ff'` and `b'0101'` literals (and `N'…'`, `_utf8mb4'…'`, PostgreSQL `B'…'`/`X'…'`/`U&'…'`) became a column with an alias, SQLite `?1` became `? 1`, and `CREATE TABLE IF NOT EXISTS name (…)` upper-cased the table name as if it were a function. These are now read as single tokens, operator characters written touching always stay touching, and `CREATE TABLE IF NOT EXISTS` bodies get the normal one-column-per-line layout.

## Format SQL now formats SQL it used to leave alone

The formatter used to return SQL unchanged when it met syntax the editor's lexer did not know. It now formats T-SQL `#temp` / `##global` temp tables and `$action`, PostgreSQL JSONB and array operators (`@>`, `<@`, `#>>`, `?|` and any custom operator, read the way PostgreSQL reads them), arrays and subscripts (`ARRAY[1, 2]`, `tags[1]`, `text[]`), psql `:variables`, MySQL `@user` and `@@system` variables, Oracle `table@dblink` links and `%TYPE` attributes, Snowflake `src:path` access, and BigQuery `[…]` arrays and `@parameters`. Oracle scripts keep each PL/SQL-ending `/` on its own line, and `OVER`, `PARTITION BY`, `WITHIN GROUP`, `WHEN [NOT] MATCHED`, `IF [NOT] EXISTS`, `CREATE OR REPLACE`, `INTERVAL`, `NULLS FIRST/LAST`, MERGE's `USING` and Redshift's `DISTSTYLE`/`DISTKEY`/`SORTKEY` now get keyword casing; `QUALIFY` is laid out as its own clause like `HAVING`.

## Minify SQL keeps what the server runs

Minify SQL dropped MySQL and MariaDB executable comments (`/*! … */`, `/*M! … */`), whose contents the server executes, and Oracle `--+` hints; both are now kept. It also no longer puts a space where there was none (MySQL rejects `COUNT (*)`), keeps Oracle's `/` block terminators on their own line, and returns the input unchanged if its result would not hold exactly the same SQL.
