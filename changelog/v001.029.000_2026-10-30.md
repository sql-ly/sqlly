# 2026-10-30

## Import and export connections for other database tools

Import From Other Tools now also reads pgAdmin's exported servers.json, the saved connections in Azure Data Studio's and VS Code's settings.json, DbGate connection environment files, and PostgreSQL pg_service.conf files, alongside DataGrip, DBeaver, TablePlus, Navicat and Redis Insight. The new File ▸ Export for Other Tools submenu goes the other way, writing the connections you pick as a pgAdmin servers.json, an Azure Data Studio / VS Code settings file, a DBeaver data-sources.json, a DataGrip dataSources.xml, a DbGate .env file, or a pg_service.conf, with folders, TLS settings and SSH tunnels kept where the target can hold them. The picker lists only the connections that tool can open, and no export ever contains a password.

## Jupyter notebooks

SQL notebooks open from and save to Jupyter .ipynb files, the format Azure Data Studio, VS Code and JupyterLab use. Code cells become SQL cells (a leading %%sql magic is dropped), Markdown stays Markdown, and a notebook opened from .ipynb saves back in that format; the new Export Jupyter toolbar button writes an .ipynb copy of any notebook. Stored outputs are not carried over in either direction.

## VS Code snippet import and export

The Snippets & Quick Actions preferences pane can import VS Code and Azure Data Studio snippet files and export SQLLY snippets as a .code-snippets file. Multi-prefix snippets become one snippet per prefix, snippets scoped to other languages are skipped, prefixes you already have are left alone, and imported snippets are kept once you click Save.
