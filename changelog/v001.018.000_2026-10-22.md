# 2026-10-22

## Color result cells by data type

A new opt-in setting, "Color cells by data type" under Settings ▸ Results ▸ General, tints every result cell's background by the kind of data it holds — numbers, dates and times, booleans, unique IDs, binary values, and text each get their own subtle theme-aware color, so mixed columns read at a glance. Your own conditional-formatting rules — color scales included — still win wherever they apply, masked columns are never tinted, the tints follow the theme when you switch it, and NULLs keep their existing styling; the whole feature stays off until you turn it on. Answers [DataGrip DBE-1274](https://youtrack.jetbrains.com/issue/DBE-1274) (color cells by data type, open for eleven years).

## Sign in to Amazon ElastiCache and MemoryDB with AWS IAM

Redis connections can now use AWS IAM authentication, so ElastiCache and MemoryDB clusters protected by IAM no longer need a static password that dies after fifteen minutes. Connect to the cluster's AWS endpoint with encryption on, choose AWS IAM, enter the IAM-enabled user id and region (optionally an AWS profile), and SQLLY signs a fresh ElastiCache or MemoryDB IAM token for that cache from the AWS credentials already on your machine each time you connect. Tokens live only in memory, are never sent over an unencrypted connection, and the same connections work from the command-line tool and the MCP server. A host SQLLY cannot read the cache name from (an IP address or a private DNS alias) gets a clear error rather than a confusing sign-in failure. Answers [Redis Insight #5693](https://github.com/redis/RedisInsight/issues/5693) (AWS IAM authentication credentials provider).

## Jump between the editor and the results grid with F6

Working entirely from the keyboard no longer breaks at the mouse: F6 moves focus from the SQL editor to the results grid and back again, so the run-read-edit loop — write the query, run it, read the grid, fix the query — never needs a click. A hidden results pane is shown when F6 jumps to it. The shortcut is remappable under Settings ▸ Keybindings ("Results: Toggle Focus Between Editor and Grid"). Answers [DbGate #1498](https://github.com/dbgate/dbgate/issues/1498) (add a keyboard shortcut to jump between the query and grid panels).

## Occurrence highlighting in the SQL editor

Selecting a word or phrase in the SQL editor now softly highlights every other place the same text appears in the script, the way VS Code and Sublime do, so repeated table names, variables, and literals are visible at a glance without opening Find. The highlight follows your selection as you move, vanishes the moment you click away, never touches the text, and can be turned off under Settings ▸ Editor ▸ General ▸ Highlight occurrences of selection. Very large scripts and long multi-word selections are skipped so selecting never slows the editor down. Answers [Beekeeper #4781](https://github.com/beekeeper-studio/beekeeper-studio/issues/4781) (highlighting a word should highlight it elsewhere in the SQL editor).

## I-beam cursor over the SQL editor

The mouse pointer over the SQL editor is now the text I-beam instead of the default arrow, so the editing surface reads as a place to click and type. The pointing hand still appears when you hold the navigation modifier over a table or column name to jump to its definition. Answers [Chat2DB #2790](https://github.com/OtterMind/Chat2DB/issues/2790) (SQL editor mouse cursor remains an arrow instead of changing to a text cursor).

## Deeply nested XML can no longer crash the cell viewer

Opening an extremely deeply nested XML value in the Cell Details panel or the structured-data viewer no longer risks crashing the app: documents nested beyond 256 levels are now refused by the tree builder and shown as formatted text instead of an expandable tree. Real-world XML is unaffected — the limit is far deeper than anything a database returns — and deeply nested JSON was already safe because the JSON parser refuses hostile depth on its own, a behavior now pinned by a test. Answers [DbGate #1256](https://github.com/dbgate/dbgate/issues/1256) (crash with "Maximum call stack size exceeded" rendering a Redis database's data).

[Redis Insight #5179](https://github.com/redis/RedisInsight/issues/5179) (rotated self-signed certificates must be re-pasted into every connection) — already have it: certificates are configured as file paths and re-read on every connect, so a rotation in place just works. [Redis Insight #6292](https://github.com/redis/RedisInsight/issues/6292) (SSH tunnels die when idle, no keepalive option) — already have it: SSH tunnels send a keepalive every 30 seconds by default (adjustable per connection), and every database socket sends TCP keepalives too. [Sequel Ace #2663](https://github.com/Sequel-Ace/Sequel-Ace/issues/2663) (the MCP server shares the UI tab's live connection) — checked, SQLly's MCP server is a separate process with its own connections, a read-only-by-default policy with per-connection modes, a hard refusal of Production connections, and an audit record per tool call.
