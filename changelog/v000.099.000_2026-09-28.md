# 2026-09-28

## Safety checks read SQL the way your database does

SQLLY's safety checks now read your SQL with the quoting and comment rules of the database you're connected to. That covers every way a server setting you can't see could change those rules, such as MySQL's ANSI_QUOTES and NO_BACKSLASH_ESCAPES, PostgreSQL's standard_conforming_strings, and version-gated MySQL comments. The checks are SELECT-only, read-only, confirm data changes, unfiltered UPDATE/DELETE, tenant scoping, and the MCP, agent and AI runs. Tricks like a quote inside a backtick or double-quoted name (`SELECT 1 AS `'`; DELETE FROM t; …`), MySQL # comments, PostgreSQL $$ blocks, Oracle q'[…]' strings, nested comments, or a DELETE followed by a SELECT with no semicolon can no longer hide a statement. If a setting could change how a statement is read, it must pass the checks under every possible reading. Input the checks can't read with certainty, such as an unterminated string or a NUL byte, is refused under SELECT-only and needs confirmation otherwise.

The rollback-wrap setting now really rolls back a last statement written without a semicolon. It refuses statements that would end the wrap early, such as COMMIT, BEGIN or MySQL's implicit-commit commands, and a failed MySQL run no longer leaves a transaction for the next run to commit. The drivers for ClickHouse, DuckDB, libSQL and Oracle now split scripts with the same rules the checks use. The Include Statistics wrapper can no longer be confused by a GO inside a string.

## Hostile names and values can no longer become SQL or commands

Values and names that come from your database are now quoted in each engine's own rules everywhere SQLLY builds SQL or commands from them. That covers value suggestions, Look Up Values, dependency lookups, ClickHouse identifiers, query parameters, generated code, dump and restore tool arguments, the external editor, and the Windows link opener. For example, a stored value ending in a backslash can no longer escape its closing quote on MySQL or ClickHouse, and a database name can no longer smuggle extra options into pg_dump or mysqldump.

## IntelliSense Improvement: @@ suggests the server's system variables

Typing `@@` now suggests the connected database's system variables. SQL Server gets its @@ functions such as @@ROWCOUNT, @@IDENTITY and @@TRANCOUNT, and MySQL/MariaDB gets its @@ system variables such as @@sql_mode and @@autocommit. Engines without them get no suggestions. Typing after `@@` filters the list by the same matching rules the rest of IntelliSense uses. A single `@` still offers only your own variables and parameters, and @@ names no longer appear in ordinary suggestion lists. Resting the pointer on a MySQL system variable explains it. This was previously an empty popup (feedback ifb_93e5).

## A distinct color for every kind of word in the editor

Keywords, functions, constants, data types, variables, numbers, strings, and comments now each get their own color in every theme. Before, keywords and function names shared the theme's accent color, and NULL and date parts looked like numbers. Highlighting now follows the connection's SQL dialect, using the real keywords, built-in functions, and types of SQL Server, PostgreSQL, MySQL/MariaDB, SQLite, and Oracle. It also tells apart words that do double duty, such as LEFT in a join versus LEFT( as a function, and CHAR( versus CAST(x AS char(10)). Column names that happen to match a function, such as year, now stay plain. Quoted names like `count`, [select], and "order" are never colored as keywords, and a quote inside a quoted name no longer paints the rest of the line as a string. Each dialect's own string forms are recognized: N'…', E'…', $$…$$, q'[…]', and MySQL's double-quoted and backslash-escaped strings.

## Hover and parameter hints for built-in functions

Rest the pointer on a built-in function to see every form it takes, what it returns, what each argument means, and an example. Rest it on a constant or data type to see what it means in your dialect. Keywords get no card. Hover cards now wait three seconds before appearing, so they no longer flash up while you read or move across code. Inside a function call, the parameter hint now describes the argument you are typing and picks the form that matches the arguments so far. Arguments that take a fixed set of words, such as the date part of DATEADD or the unit of TIMESTAMPDIFF, list those words and offer them first in autocompletion. The hint now opens directly under the line you are typing, with the suggestion list below it, so the two never cover each other or your code. Inside a function's parentheses, such as COUNT(, suggestions now lead with the columns of the query's tables, and @@ system functions no longer head the list unless you type @. Function suggestions now come from the connection's dialect, with each function's signature shown beside it. About 1,400 functions and 900 keywords are documented across the five dialects.

## Send Feedback reports no longer vanish on Send

Pressing Send in the Send Feedback window, or in a popped-out Improve IntelliSense window, could close the window before the report was handed off, so it was silently dropped: no upload, nothing saved, no error. The window now closes only after the report is handed off. Both kinds of feedback are written to a local file first and stay there until the server accepts them. Anything not yet uploaded is retried every five minutes, and at every launch, until it goes through. The old five-hour give-up is gone.

## Numbered, bolder arrows in Send Feedback

Arrows in the Send Feedback screenshot are thicker with a larger pointer. Each arrow now carries a numbered badge at its tail, so your message can say "see #2". The numbers are burned into the uploaded screenshot and sent with the arrow details, so the team sees the same numbering.
