# 2026-10-20

## SSH host picker reads included config files

Picking an SSH host from your ~/.ssh/config now also lists the hosts defined in files that config pulls in with Include lines, including paths that start with `~`, paths relative to ~/.ssh, and patterns such as `conf.d/*.conf`. Before, hosts kept in included files were missing from the picker.

Answers competitor issue [Sequel Ace #2744](https://github.com/Sequel-Ace/Sequel-Ace/issues/2744).

## MySQL accounts that sign in through PAM or LDAP can connect

Some MySQL accounts (PAM and LDAP authentication) ask the client to send the password as plain text. SQLLY now does that when the connection's TLS setting verifies the server's certificate (Verify CA or Verify full, the default), so the password only ever travels encrypted to a server you have checked. With TLS set to Disable or Require, the request is still refused, and the error now says which setting to change instead of showing the driver's message.

Answers competitor issues [Beekeeper Studio #4778](https://github.com/beekeeper-studio/beekeeper-studio/issues/4778), [DbGate #1544](https://github.com/dbgate/dbgate/issues/1544) and [Sequel Ace #2681](https://github.com/Sequel-Ace/Sequel-Ace/issues/2681).

## MySQL backups and restores keep non-English user names intact

Backup and restore for MySQL and MariaDB now hand the user name to mysqldump and mysql in their settings file, next to the password, instead of on the command line. On Windows the command line could change letters such as ö, so a user like admin_björn could be refused as admin_bj.

Answers competitor issue [DBeaver #42389](https://github.com/dbeaver/dbeaver/issues/42389).

## Direct TLS for PostgreSQL 17 behind a TLS proxy

PostgreSQL connections gain a "Direct TLS (PostgreSQL 17+)" option next to the TLS setting. It starts the encrypted connection straight away, the way PostgreSQL 17 allows, so SQLLY can reach databases behind a TLS proxy such as Caddy or Traefik that routes several servers on one port by host name. Pasted connection strings with `sslnegotiation=direct` tick it, credential files carry it, Open in Terminal passes it on to psql, and an older server that refuses the handshake gets an error saying the option needs PostgreSQL 17.

Answers competitor issue [DBeaver #42359](https://github.com/dbeaver/dbeaver/issues/42359).

## Query parameters and variables reach PostgreSQL array slices

A declared `-- sqlly param:` value or a `-- sqlly set` variable written inside square brackets, such as `my_array[@lo:@hi]` or `arr[${first}]`, is now filled in on PostgreSQL, DuckDB and every other engine that does not quote names with brackets. Before, SQLLY treated every `[` as the start of a SQL Server style quoted name and left the placeholder untouched, so the query reached the server with `@lo` still in it. SQL Server, Azure SQL, Access and SQLite still read `[name]` as a quoted name and leave it alone.

Found while checking competitor issue [DataGrip DBE-25057](https://youtrack.jetbrains.com/issue/DBE-25057) (SQLLY never had that issue's unwanted parameter prompt).

## Completion knows the columns of your CTEs

Typing `cal.` after `FROM my_cte AS cal` now offers the CTE's columns: the names its query produces, or the names in its column list when you write `WITH my_cte (a, b) AS (…)`. This works in the main query and inside a later CTE that reads an earlier one. Before, a CTE was known by name only, so its alias completed nothing.

Found running the query from competitor issue [DBeaver #42293](https://github.com/dbeaver/dbeaver/issues/42293). The issue itself, a `FROM` inside `EXTRACT`, `SUBSTRING`, `TRIM`, `OVERLAY` or `IS DISTINCT FROM` breaking column resolution, was never a problem in SQLLY.

## Completing inside a quoted name replaces the whole name

When you place the caret inside an already-quoted name, such as right after the opening backtick of `` `netru_database` ``, and accept a suggestion, SQLLY now replaces the whole quoted name through its closing quote. Before, the rest of the old name and its closing quote stayed behind, leaving text like `` `staging_netru_database`netru_database` ``. A quote you are still typing never swallows text up to some later quote.

Answers competitor issue [Sequel Ace #2245](https://github.com/Sequel-Ace/Sequel-Ace/issues/2245).

## Statement keywords and declared variables in completion

At the start of a statement, completion now offers BEGIN, DECLARE, WITH, MERGE, ALTER, DROP, TRUNCATE TABLE, COMMIT, ROLLBACK, IF and WHILE alongside SELECT, INSERT and the rest, including on a new line after a T-SQL statement with no semicolon. Inside clauses they stay out of the way. A variable you are typing, such as `@us`, no longer suggests itself above the declared `@user_name` it should complete to.

Answers competitor issue [DbGate #1223](https://github.com/dbgate/dbgate/issues/1223).

## Competitor issue check

We checked these open issues from other SQL clients against SQLLY. None of them is a problem SQLLY has, or SQLLY already has the feature.

- [DBeaver #42384](https://github.com/dbeaver/dbeaver/issues/42384) (idle-connection setting lost on save): checked, SQLLY saves every connection setting, on or off, and existing tests reload them after a save.
- [Sequel Ace #2077](https://github.com/Sequel-Ace/Sequel-Ace/issues/2077) (SSH password change not saved when other fields change too): checked, one Save stores the database password, the SSH password or key passphrase, and the proxy password together in your system keychain.
- [Sequel Ace #2266](https://github.com/Sequel-Ace/Sequel-Ace/issues/2266) (SSH password asked for on every connect): checked, a saved SSH password is read back from the keychain on every connect and reconnect.
- [Azure Data Studio #26444](https://github.com/microsoft/azuredatastudio/issues/26444) (saved password lost after restarting): checked, saved passwords live in your system keychain and are read back after a restart; if one is missing, SQLLY says so instead of signing in with a blank password.
- [Beekeeper Studio #4706](https://github.com/beekeeper-studio/beekeeper-studio/issues/4706) (backup tool path not remembered): already have, SQLLY finds pg_dump, mysqldump and friends itself, and a path you set under Tools ▸ Options ▸ Advanced ▸ Database tools is saved.
- [HeidiSQL #2604](https://github.com/HeidiSQL/HeidiSQL/issues/2604) (unreachable servers stop the app from opening): checked, a restored workspace opens disconnected until you choose Connect, and a server that can't be reached only shows an error in the status bar.
- [DBeaver #42360](https://github.com/dbeaver/dbeaver/issues/42360) (parameter prompt for `${timestamp}` inside a comment): checked, SQLLY only asks for values you declare with `-- sqlly param:`, and never reads placeholders in comments.
- [DataGrip DBE-25057](https://youtrack.jetbrains.com/issue/DBE-25057) (parameter prompt for a PostgreSQL array slice): checked, `my_array[min_bound:max_bound]` runs as written; a colon is never a parameter.
- [DataGrip DBE-18646](https://youtrack.jetbrains.com/issue/DBE-18646) (colon syntax such as `metadata:country` prompts for a parameter): checked, a colon is never a parameter on any engine.
- [DataGrip DBE-27337](https://youtrack.jetbrains.com/issue/DBE-27337) (a way to run a query without parameter substitution): already have, a query with no `-- sqlly param:` or `-- sqlly set` line is sent exactly as written.
- [Beekeeper Studio #4702](https://github.com/beekeeper-studio/beekeeper-studio/issues/4702) (SQL Server asks for parameters on a query that has none): checked, nothing is substituted or asked for unless you declare it.
- [HeidiSQL #2469](https://github.com/HeidiSQL/HeidiSQL/issues/2469) (a doubled apostrophe followed by a semicolon inside strings breaks the script): checked, SQLLY splits that script correctly on every engine.
- [Sequel Ace #2258](https://github.com/Sequel-Ace/Sequel-Ace/issues/2258) (double-clicking a result cell runs a COUNT query): checked, double-clicking a cell only opens the value viewer; SQLLY runs a count only when you click Calculate total rows.
- [DBeaver #42381](https://github.com/dbeaver/dbeaver/issues/42381) (join suggestions vanish after ON when a WHERE clause follows): checked, both joined tables' columns are offered after ON whether or not later clauses follow.
- [HeidiSQL #2439](https://github.com/HeidiSQL/HeidiSQL/issues/2439) (column suggestions without a table alias): already have, a single-table query offers its columns by bare name, before or after the FROM clause.
