# 2026-10-26

## Competitor issue check

Checked a keyboard, focus, and tab-navigation batch against SQLly. [Beekeeper Studio #4767](https://github.com/beekeeper-studio/beekeeper-studio/issues/4767) (keyboard connection-type selection) — already available through the keyboard-capable connection engine selector with a default selection. [Chat2DB #2718](https://github.com/OtterMind/Chat2DB/issues/2718) (New Console shortcut freezes) — checked, SQLly opens a new query directly with Cmd/Ctrl+N, while Cmd/Ctrl+Shift+L is the editor's select-all-occurrences command. [HeidiSQL #2495](https://github.com/HeidiSQL/HeidiSQL/issues/2495) (redo shortcut missing) — already configurable, with Cmd+Shift+Z on macOS and Ctrl+Y or Ctrl+Shift+Z on Windows and Linux. [HeidiSQL #2493](https://github.com/HeidiSQL/HeidiSQL/issues/2493) (letter keys trigger shortcuts in text fields) — checked, editor and results shortcuts are scoped to their own key contexts and text input uses standard controls. [Sequel Ace #2187](https://github.com/Sequel-Ace/Sequel-Ace/issues/2187) (delete a result row from the keyboard) — Delete or Backspace stages the selected row for deletion, with review before saving. [Sequel Ace #2090](https://github.com/Sequel-Ace/Sequel-Ace/issues/2090) (horizontal scrollbar overlaps the last row) — checked, the grid reserves a separate scrollbar gutter and the SQL editor provides five lines of scroll-past-end space.

## Competitor issue check: import, export, and backup

Checked an import, export, and backup batch against SQLly. [DataGrip DBE-27386](https://youtrack.jetbrains.com/issue/DBE-27386) (choose a copy format without changing the default extractor) — already available in the results grid's Copy As submenu, with CSV, JSON, JSON Lines, Markdown, and INSERT choices. [DbGate #1471](https://github.com/dbgate/dbgate/issues/1471) (import a database from a SQL file) — already available through File → Run SQL File, which streams scripts with progress, cancellation, and failure controls. [DbGate #1308](https://github.com/dbgate/dbgate/issues/1308) (custom backup folder) — dump and scheduled-task dialogs accept custom output files or folders, and the SQL library folder is configurable. [DbGate #1231](https://github.com/dbgate/dbgate/issues/1231) (backup and restore for MySQL, MariaDB, and SQL Server) — MySQL and MariaDB have native mysqldump/mysql support, while SQL Server has reviewable Backup / Restore statements. [Sequel Ace #2392](https://github.com/Sequel-Ace/Sequel-Ace/issues/2392) (exported filename contains only the extension) — checked, SQLly suggests nonempty database-based dump filenames and result filenames, with existing filename tests.

## Translations: language switching updates the whole app

Switching language now updates everything already on screen: automatic tab names, Explorer folder names and Redis notes, the AI Playground provider list, window titles, and the native menu bar (which now follows the frontmost window). Tab names are saved in a language-neutral way, so a session saved in Spanish restores correctly in English, and automatic tab naming keeps working. Dropdowns throughout the app (dump, export, data compare, search, tunnel profiles, connection editor, MCP activity, ER diagram, and others) now act on the selected entry rather than its translated wording. This fixes options that silently did nothing after a language change, the PostgreSQL dump format always falling back to Custom in Spanish, and user profiles whose names clashed with built-in entries. Also fixed: editing a tunnel profile no longer resets its proxy kind and SSH authentication.

## Translations: custom translation files and Settings

A custom translation file with a few outdated keys no longer gets thrown away at startup: the valid entries load, and the Language settings show what was skipped. If applying a new file fails, the previous language and translations are restored exactly. Text lookups in the results grid and across the interface are faster.

## Translations: browser preview keeps early language updates

The browser preview no longer loses the first language or wording update it receives while the app is still starting.

## Clearer error messages

Errors no longer repeat their prefix ("Server capability not supported: Server capability not supported: …", or a doubled "Connection error:" on Redis), and the remote engine reports unsupported features as unsupported again. A few query errors got back their "Query execution error:" prefix.
