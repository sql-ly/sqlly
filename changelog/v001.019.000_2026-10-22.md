# 2026-10-22

## Lock a result grid into its query

A padlock now sits in front of every result's name. Clicking it writes one `/* sqlly lock */` block of directives into the query that captures the grid exactly as it looks: column order, hidden and frozen columns, column widths, sort, grouping, column filters, foreign-key labels, column formats and rounding, conditional formatting rules, the pivot and chart setup, which view is open, and the results layout. Running the query again, on any machine, brings the same grid back; clicking the padlock again rewrites the block to match what is on screen and folds any stray display directives into it. New directives make this possible and can be typed by hand too: `-- sqlly grid:` arranges columns, sorts, groups, and filters; `-- sqlly conditional:` adds conditional formatting rules for one query; `width=` on `-- sqlly format:` sets a column width in dp, a unit tied to the grid font size so a column keeps showing the same characters at any font size or zoom; and `result:` lets a pivot or chart directive target a result set other than the first.

## Computed columns written as Excel formulas

Result grids can now grow columns computed with Excel formulas, for everyone who knows Excel better than SQL. Right-click a column header and choose Add Computed Column… to open a formula bar above the grid: type a name and a formula, and while it reads correctly every reference is colored and the grid outlines the cells it uses, the way Excel shows a formula's inputs. Columns are written `!Name`, the row before `!Name[1]`, a fixed row `!Name[$1]`, ranges like `!Qty[2]:!Qty`, and declared variables `@name`; IF, IFS, IFERROR, SWITCH, COALESCE, the math, text, and date functions, and Excel's operators, precedence, and error values all work the same as in Excel. The column is saved in the query as a `-- sqlly column:` directive, so it comes back on every run, travels with the file, and is captured by the lock; selecting one of its cells shows the formula in the bar with the same coloring.

## Excel exports keep the grid and the pivot

Exporting a result to Excel now produces a workbook that looks like the grid: the same column order, widths, hidden and frozen columns, number and date formats from the query's directives, and conditional formatting as real Excel rules. Computed columns arrive as live Excel formulas (with their values filled in), and variables they use become named values in the workbook. When the result has a pivot set up, a second sheet named after the result holds the pivot exactly as shown, including collapsed groups, sort order, filters, and totals.
