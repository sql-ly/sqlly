# 2026-10-21

## Filter and open referenced rows on binary keys

Binary key values, such as a UUID stored as BINARY(16) or a bytea hash, now work with the results grid's filter actions. "Add WHERE column = value" compares the real bytes, written as the database's own hex literal (`0x…`, `X'…'`, or `'\x…'`). Before, it wrote the grid's `<16 bytes>` label into the query as text on PostgreSQL and SQLite, and did nothing on SQL Server and MySQL. A value shown only as a preview (long text or large binary cut short in the grid) now offers just the IS NULL and IS NOT NULL tests, since the preview is not the whole value. The grid's quick filters do the same for binary cells, where filtering on the `<16 bytes>` label used to match every value of that length.

Open Referenced Row now follows a foreign key whose value is binary instead of reporting it as NULL. It also builds valid SQL on PostgreSQL, MySQL, MariaDB, SQLite, and every other engine that limits rows with LIMIT or FETCH FIRST: the WHERE clause used to land after the LIMIT, which is a syntax error.

Answers [Sequel Ace #2068](https://github.com/Sequel-Ace/Sequel-Ace/issues/2068) and [Sequel Ace #2361](https://github.com/Sequel-Ace/Sequel-Ace/issues/2361).

## Trusting a new SSH host works

The first connection to an SSH host SQLly had not seen before showed the trust dialog, but trusting the key did nothing and the connection failed. Behind the dialog, the tunnel had already stopped waiting for the answer. The dialog's answer now reaches the tunnel, so Trust saves the key and the connection opens, both for a new host and for a host whose saved key was removed.

Answers [Sequel Ace #2040](https://github.com/Sequel-Ace/Sequel-Ace/issues/2040).

## Idle connections stay alive, and dead ones no longer hang the next query

SQL Server, PostgreSQL, and MySQL connections now send a small keepalive after a minute without traffic. Firewalls, VPNs, and cloud load balancers that silently drop idle connections (some after only four minutes) no longer cut off a connection SQLly is keeping ready for your next query. A connection that really died is noticed within about a minute and a half, and the next query opens a fresh one instead of waiting on the dead one. On SQL Server, a kept connection that does not answer within 5 seconds is replaced the same way, which also covers switching networks or reconnecting a VPN.

SQLly never needed a restart after an idle period: kept connections are already replaced after five idle minutes, and Cancel always ends a stuck run. This removes the wait before that happens.

Answers [DBeaver #42373](https://github.com/dbeaver/dbeaver/issues/42373) and [DbGate #1380](https://github.com/dbgate/dbgate/issues/1380).

## Certificate checks through SSH tunnels and proxies use the server's name

With TLS set to Verify full, a SQL Server, PostgreSQL, or MySQL connection through an SSH tunnel, proxy, or Kubernetes port-forward checked the server's certificate against the tunnel's local address (127.0.0.1) instead of the server's name, so the check failed even with the right certificate. The certificate is now checked against the server name in the connection editor. On SQL Server the login also carries the real server name through a tunnel, which Azure SQL needs to route it. Certificate files are still read from your own machine, which is where SQLly does the TLS work.

Answers [Sequel Ace #2132](https://github.com/Sequel-Ace/Sequel-Ace/issues/2132).

## "No route to host" on macOS explains Local Network access

On macOS 15 and later, an app needs your permission to reach addresses on your local network, such as a Parallels VM, an OrbStack container, or a server on your LAN. When that permission is off, connections fail with a bare "No route to host". SQLly now says why it asks for local network access, and that error now tells you to allow SQLly under System Settings → Privacy & Security → Local Network.

Answers [DataGrip DBE-22995](https://youtrack.jetbrains.com/issue/DBE-22995).

## SQL previews and command output use the editor font

The Preview SQL tab, which shows the SQL for staged row edits, the output of command-line tools, the CLI install line in MCP settings, and the license texts in Open Source Licenses showed their text in Helvetica on macOS instead of a monospaced font. They asked for a font called "monospace", which no system has, so the app fell back to its last-resort font. ## Valid PIVOT, UNPIVOT and APPLY queries no longer get false column warnings

While connected, SQLly checks your SQL as you type and underlines names it cannot find. A valid query that filtered on a column produced by PIVOT or UNPIVOT, by CROSS APPLY or OUTER APPLY, or by OPENJSON … WITH (…) on SQL Server got a "column not found on any table" warning anyway. The same happened on PostgreSQL 16 and later for a subquery in FROM without an alias. Those sources are now treated like any other derived table: their columns are not checked against the database's tables, while a mistyped column in an ordinary query is still caught. On Oracle, results built on PIVOT, UNPIVOT or CROSS APPLY are now read-only in the grid, since their rows are not rows of the table underneath.

Answers [DataGrip DBE-16320](https://youtrack.jetbrains.com/issue/DBE-16320) (valid PIVOT and UNPIVOT marked as errors).

## EXECUTE IMMEDIATE is highlighted on MySQL and MariaDB

In MariaDB's EXECUTE IMMEDIATE, the word IMMEDIATE was drawn as plain text. It is now highlighted as a keyword, and EXECUTE IMMEDIATE appears in completion with a short description.

Answers [HeidiSQL #2619](https://github.com/HeidiSQL/HeidiSQL/issues/2619) (IMMEDIATE not highlighted).
