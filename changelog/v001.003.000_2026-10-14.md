# 2026-10-14

## SQLly in the browser no longer calls itself a demo when it runs through a bridge

When SQLly runs in the browser through a SQLly Embedded bridge or a relay proxy, it no longer says it's an "in-tab demo" that "cannot reach your servers". The loading screen now says SQLly is connecting to the databases your administrator set up and that passwords stay on the server. The pitch for the desktop app and the rotating "in that same second" facts are gone from it, and the tab title is just "SQLLY". The welcome screen invites users to pick one of the connections their administrator set up. Trying to add or change a connection there, including an Azure SQL one, explains that connections are set up on the server and to ask an administrator, rather than pointing at a credential file. The standalone in-browser preview keeps its demo wording.

## SQLly in the browser stops pointing Embedded users at the desktop app

About fifty messages for features a browser can't offer (opening files, external editors, Git, Open in Terminal, SSH tunnels, Entra sign-in, local AI and more) used to say they were "not available in the browser preview — use the desktop app". When SQLly runs through a SQLly Embedded bridge or relay proxy, they now say the feature isn't available when SQLly runs in a browser, without the desktop pitch. The security dialog no longer calls itself "illustrative only" there, because it manages the real server through the bridge. The Entra, project-file and Azure firewall notes explain what the user can do instead. The standalone browser preview keeps its original wording.
