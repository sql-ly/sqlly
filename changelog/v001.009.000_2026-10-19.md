# 2026-10-19

## JSON exports keep every column when column names repeat

A result such as `SELECT 1 num, 2 num, 3 num` used to export and copy as JSON with the same key three times, and any JSON reader then kept only the last value. JSON and JSON Lines (copy, save and streamed export) now give repeated names `_2`, `_3` suffixes, the same way the SQL, XML and Excel exports already did, so every column survives. Suffixes also skip names another column already has, so `num, num, num_2` no longer produces two `num_2` keys.

Answers competitor issue: Beekeeper Studio [#4818](https://github.com/beekeeper-studio/beekeeper-studio/issues/4818) ("Copy to Clipboard" only copies the last column when there are duplicate column names).

## The IN filter accepts pasted "Copy for IN" lists

Pasting a SQL value list into the grid filter's "in" / "not in" box now works: the "Copy for IN" output (`[Id] IN (1, 2, 3)`), a bare `(1, 2, 3)` list, and one value per line inside parentheses all filter on every value. Before, the first value kept the opening parenthesis and never matched. Quoted text values are read as SQL literals, so `N'a, b'` stays one value and `''` becomes an apostrophe. A plain typed list still works as before.

Answers competitor issue: Beekeeper Studio [#4779](https://github.com/beekeeper-studio/beekeeper-studio/issues/4779) (IN filter ignores the first value pasted from "Copy for IN statement").

## Fill one value down a selection

Pasting a single copied value or row over a selected range of cells in an editable grid now fills every selected row, the way a spreadsheet does. A single value fills every selected column too. Before, only the first selected row changed. Each filled row is its own staged edit, marked in the grid and listed in Preview SQL, so what you see marked is exactly what Save writes. Pasting a multi-row block, or into scattered Cmd-clicked cells, works as before.

Answers competitor issue: DataGrip [DBE-27126](https://youtrack.jetbrains.com/issue/DBE-27126) (a multi-row paste shows every row changed but saves only the first).

## Competitor issue check: results grid trust

We checked these open issues from other SQL clients against SQLly. None of them is a problem SQLly has. New tests now also guard the locale-safe number editing and the JSON-null display.

- Azure Data Studio [#26344](https://github.com/microsoft/azuredatastudio/issues/26344) (decimals exported to JSON don't match the grid under a non-US regional format): checked, not a problem we have. SQLly writes decimals into every export digit for digit, and no export depends on the system locale.
- Azure Data Studio [#26194](https://github.com/microsoft/azuredatastudio/issues/26194) (export ignores the grid filter): checked, not a problem we have. Export and copy use the filtered, sorted rows you see, and a filter that hides every row exports nothing rather than everything.
- Azure Data Studio [#26222](https://github.com/microsoft/azuredatastudio/issues/26222) (editing `2.3` to `2.5` under a German locale saves `25.0`): checked, not a problem we have. Edited numbers are read the same way on every locale; decimal values go to the server exactly as typed.
- Beekeeper Studio [#4732](https://github.com/beekeeper-studio/beekeeper-studio/issues/4732) (a JSON `null` and a SQL NULL look the same): checked, not a problem we have. A JSON `null` shows as the text `null`; only a real SQL NULL shows as NULL.
- DBeaver [#42319](https://github.com/dbeaver/dbeaver/issues/42319) (cells flip between NULL and their values while scrolling): checked, not a problem we have. Rows that are still loading draw blank, never as NULL, and fetched values never change while you scroll.
- DbGate [#1501](https://github.com/dbgate/dbgate/issues/1501) (the grid never shows the last rows of a result): checked, not a problem we have. The row count and the scrollable range come from the same total, and the finished result is always reachable to its last row.
- DbGate [#1537](https://github.com/dbgate/dbgate/issues/1537) (a paged, sorted, filtered table shows some rows twice and skips others): checked, not a problem we have. SQLly does not page table data with OFFSET; sorting and filtering work on the whole result.
- HeidiSQL [#2596](https://github.com/HeidiSQL/HeidiSQL/issues/2596) (Down arrow on the last row of a read-only result starts an insert and shows an error): checked, not a problem we have. Arrow keys stop at the last row and never add one.
- DataGrip [DBE-27126](https://youtrack.jetbrains.com/issue/DBE-27126) (a multi-row paste shows every row changed but saves only the first): checked, not a problem we have. Each pasted row becomes its own saved change, and only rows that will be saved are marked. SQLly does not edit CSV files as tables.
- Sequel Ace [#2652](https://github.com/Sequel-Ace/Sequel-Ace/issues/2652) (after an inline edit, arrow keys make a wide grid jump sideways): checked, not a problem we have. The grid scrolls only when the selected cell is out of view, by the smallest amount.
