# 2026-10-14

## Dependency refresh across the client workspace

Every crates.io dependency in the client workspace was moved to its latest release, except `keyring` (whose 4.x line is a ground-up rewrite that is tracked as a separate migration). The GPUI toolkit move is its own entry below. The notable moves: the SQL Server driver (tiberius) went to 0.13, which finally takes it off the old rustls 0.21 stack and closes three long-standing rustls advisories; the SSH tunnel library (russh) went to 0.64; the MCP server library (rmcp) went to 3.5; DuckDB went to 1.10506; and rustls itself went to 0.23.46, which fixes RUSTSEC-2026-0346/0347/0349. The new tiberius release also added bounded default timeouts on every SQL Server round-trip; SQLly explicitly disables those so long-running queries keep running until cancelled or the profile's own statement timeout fires, exactly as before.

## UI toolkit moves to GPUI Kit 0.7

The desktop app, the browser build and the results grid (sqlly-datatable 8.0.0) move to the latest GPUI Kit: gpui-component and its icon set 0.7.3 on top of gpui 0.3.9. The toolkit now draws dialogs, side sheets and toast notifications itself in every window, so SQLly no longer hosts those layers by hand; they now also cover the custom titlebar on Windows and Linux, like any other modal. The new gpui brings a fix for list rows laid out wrongly far down long lists, a fix for window drags that stuck after a native menu closed on macOS, a fullscreen-exit fix for the macOS traffic lights, a window memory leak fix, and correct focus tracking in the browser build. Context menus no longer pull focus back to where they were opened, the date picker in the row editor keeps writing plain `YYYY-MM-DD` dates, and the browser build ships the five icons the new toolkit added. The macOS backend copy that strips private AppKit calls for the Mac App Store edition was refreshed to the matching gpui release.
