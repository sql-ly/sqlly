# 2026-09-29

## Feedback reports include your app settings

Send Feedback and Improve IntelliSense (F2) reports now include your app configuration settings (editor, appearance, formatting, results, keybindings, AI and other preferences), so a problem can be reproduced with your exact setup. Both dialogs now say so, and say plainly that none of your connection credentials or API keys are included. Only settings files are read. Saved connections, sign-in accounts, history and session state are never read, and anything that looks like a secret (password, token and API-key fields, URL credentials and query strings, command-line arguments and environment variables) is replaced with "[redacted]" before the report leaves your machine.

## IntelliSense feedback sends literals unless you mask them

The Improve IntelliSense dialog now sends your query exactly as typed by default, because a literal's value is often what the completion problem depends on. Choose the new Mask literals button to replace string literals and comments with `<redacted>` in the preview and in the report. It replaces the old Show literals button, which worked the other way around.

## IntelliSense settings pane with hump and schema matching switches

Settings ▸ Editor ▸ Defaults is now Settings ▸ Editor ▸ IntelliSense, and its wording makes clear the settings apply to every query tab rather than per query. The pane has three new switches, all on by default. "Include the AS keyword" controls whether an accepted table's alias is written as Orders AS o or Orders o, for both the automatic and the second-suggestion alias modes (the second-suggestion mode previously always wrote it without AS). "Match camel humps and initials" can be turned off so suggestions only match where the typed text appears in the name, ignoring case. "Include schema name in searching" lets dboM or dbom find dbo.Make; turn it off to search only object names unless you type the schema and a dot.

## IntelliSense Improvement: schema-qualified names are a contains search, and camel chunks must start a word

Typing after a schema and a dot (for example `dbo.ev`) now offers every object in that schema whose name contains the typed text, ranked with names that start with it first, then names with a word that starts with it, then the rest; before, only prefix and camel matches were offered, so tables such as TrackedEvents, Devices and Reviews were missing. Camel-hump matching is also stricter: each capitalised chunk you type must begin a word of the name, so GN and GeNe find GeoNetworks but GeNw no longer does. Typing in capitals still falls back to a case-insensitive prefix match (GEONe still finds GeoNetworks), ranked below a table whose words it matches exactly. Regression tests cover each case with hump matching on and off (feedback ifb_2ff4).

## IntelliSense Improvement: aliases are added when accepting a schema-qualified table

Accepting a table after typing its schema and a dot (for example `from dbo.su` → Subscriptions) now adds the alias just like accepting an unqualified table does, following the chosen alias rule: capital letters to lower case (s), capital letters including the schema (ds), or auto based on join (first letter, numbered when already taken, e.g. s2). Before, the dotted name hid the FROM/JOIN position, so no alias was written even with auto-add on. With auto-add off the alias is offered as the follow-up suggestion instead, and with Do not suggest nothing is added (feedback ifb_3edd).

## IntelliSense Improvement: no columns right after a finished WHERE, HAVING or ON test

Once a test in a WHERE, HAVING or JOIN ON clause is complete (for example `BirthDate > '2000-01-01'`, `Id IN (1, 2)`, `x IS NOT NULL`, or `x BETWEEN 1 AND 5`), the popup no longer offers columns. While the caret still touches the finished value nothing is offered; after a space, tab or new line the popup offers AND and OR first, then the clauses that can follow (GROUP BY and ORDER BY after WHERE; WHERE and the JOIN family after ON). Columns come back as soon as you type AND or OR, and a test still missing its right-hand side keeps offering them (feedback ifb_6f67).

## SELECT-only connections allow session SET statements

A connection set to allow SELECT statements only no longer refuses session settings such as `SET NOCOUNT ON;` with "statement starts with SET, not SELECT". Settings that only change how your session reports, plans, waits or formats results are allowed before or between queries, including with no semicolons in T-SQL scripts: NOCOUNT, XACT_ABORT, the ANSI options, STATISTICS and SHOWPLAN, isolation level, lock and statement timeouts, date formats, time zone, search_path, planner switches, and your own variables. Settings that could reach further stay refused: server-wide (GLOBAL / PERSIST) settings, passwords and role or authorization changes, anything that makes a transaction read-write, settings that change how SQL is read (sql_mode, NAMES / character sets, QUOTED_IDENTIFIER, standard_conforming_strings), and any SET combined with a data change.

## Send Feedback arrows show their numbers and point where you press

In the Send Feedback dialog, each arrow's number badge is now readable on the screenshot preview. A large window (a 4K screen, for example) is shrunk so far to fit the dialog that the badge digits used to vanish. The preview now draws the number badges three times larger and keeps arrows and badges at a readable size however far the screenshot is shrunk; the uploaded screenshot is unchanged. Drawing an arrow now puts the arrowhead where you press, the thing you're pointing at, and the numbered tail follows as you drag.
