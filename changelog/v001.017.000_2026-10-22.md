# 2026-10-22

## Settings search finds values, and the search box has a clear button

Searching Settings now matches what a setting is set to, not just its name
and description: text-field contents, numbers in steppers, and dropdown
choices on every pane, plus a few labels and buttons the search used to
skip. A field whose value matches is outlined and scrolled into view.
Settings you change are findable by their new values right away, without
reopening the dialog. API keys and agent environment variables are never
searched. An × in the search box clears it and brings back the full list.

## SQL formatting moved to Editor ▸ Formatting

The SQL ▸ Formatting settings now live at Editor ▸ Formatting, which until
now only pointed at them, and the SQL folder is gone. A dialog last left on
the old pane reopens on the new one.

## Formatter puts FROM tables and WHERE conditions on their own indented lines

Two new settings under Editor ▸ Formatting ▸ Clause layout choose where a clause's body starts: "Table after FROM" and "First condition after WHERE / HAVING". Each is either "New line, indented" or "Same line as the keyword". The new default is "New line, indented", so Format SQL now puts the first table on its own line under FROM (with its JOINs lined up beneath it, and an ON on its own line indented one step further) and the first WHERE or HAVING condition on its own line, aligned with the AND/OR lines that follow. Pick "Same line as the keyword" to keep the previous layout. The Compact and Preserve Existing presets keep both on the keyword's line, a comment written right after FROM or WHERE stays on that line, and the live preview shows the change as you switch.

## Double-click a result cell to copy its value

Double-clicking a cell in a results grid now copies that cell's value to the clipboard and shows a short "Value copied" toast. The value is the same text Copy (Cmd+C) gives for a single cell — NULL, binary hex, and dates read the same, a masked column copies its masked value, and a long value shown as a preview is fetched in full before it is copied. Double-click used to open the Structured Data Viewer for cells holding JSON or XML (and did nothing anywhere else); that viewer is still on the cell's right-click menu and in the Cell Details panel. Double-clicking a pivot cell still drills through to its rows.

## Results grid hides the edit pencil on rows that can't be edited

The pencil in the results grid's row gutter now only appears when the row could actually be opened for editing. It is hidden when there is no connection, the engine has no row editing (ClickHouse, Redis), the connection is SELECT-only, read-only by production guard, or auto-rolls back changes, the results are a later result set of a batch or were restored from history, or the query isn't a simple single-table SELECT (joins, derived tables, or a select list made only of aggregates like `count(*)`). The eye (view row) icon still shows everywhere. Rows the server still refuses after looking at the table (no primary key, key not in the results, row deleted since) continue to explain why in the editor.

## Natural-language dates in date comparisons

After a comparison on a date column (`WHERE OrderDate =`, `created_at >=` and the
like), Ctrl+Shift+Space now opens a card for typing a date in plain words: today,
yesterday at noon, last wed at 3, november, q3 2025, ytd, past 7 days, from mon to
fri, christmas and many more. The card shows what the phrase means as you type;
Enter writes the exact literal for the column's precision and the engine's own
spelling, and turns a period into a range (`BETWEEN` by default, or the exact
`>= start AND < next` form). What you typed is kept in a `--sqlly date:` comment
with a ↻ button that re-evaluates the date, and a statement holding such dates
gets a Refresh dates button that updates all of them (also in the command
palette). A new Date & time convenience section under Settings ▸ Editor ▸
IntelliSense turns it on or off and sets range conversion, range style, what a
day or month on its own means, the first day of the week, how a bare hour is
read, where to-date periods end, the fiscal year start, the comment, the refresh
buttons, refreshing before every run, and whether date-like column names count
as dates when the type is unknown. Elsewhere Ctrl+Shift+Space still looks up
column values.

## Format Document has its own shortcut

Format Document (the whole query, whatever is selected) is now Alt+Shift+F
(Shift+Option+F on macOS), matching VS Code, and Format Selection moved to
Cmd+K Cmd+F (Ctrl+K Ctrl+F on Windows and Linux). Both can be changed under
Settings ▸ Workspace ▸ Keyboard Shortcuts.
