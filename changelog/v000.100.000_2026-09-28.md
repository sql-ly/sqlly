# 2026-09-28

## Faster grid filtering: quick filters, pausable conditions, saved filters, and a filter language

Right-click any result cell to filter by its value (equals, not equals, contains, IS NULL, IS NOT NULL). Quick filters always narrow what's shown, match the text the grid displays (so a formatted number like 1,234 keeps its row), and leave header value checklists in place. Each condition in the filter builder has a checkbox that pauses it without deleting it, and nested condition groups render at every depth. Filter sets can be saved by name for a table on a specific connection, server and database; one can be marked as the default so it applies whenever that table's grid opens. Saved filters follow their columns by name, so they work whatever the query's column order, and say when a column they need is missing. A default applies once per fresh result, never over a filter you set yourself, and never to multi-statement batches. Result sets too large to filter in the app show a note instead. The builder also accepts a typed expression such as `status = active, created >= LAST WEEK`, with starts-with, ends-with and negation operators, partial dates, and relative dates worked out in the grid's display time zone each time a saved filter is applied. Large whole numbers stay exact, and Apply to Query writes date literals each engine reads unambiguously. A column header's Top Values… window lists the 30 most common values with counts, and clicking one filters the grid; on very large results it says how many rows it counted. Copy Distinct Values and Copy Top 25 Values copy plain lines, and copy nothing (with a note) when the filter hides every row.

## Grid editing tools: cell transforms, value generators, find & replace, and copy staged SQL

A text cell's right-click menu can change case, trim whitespace, or remove diacritics. Remove diacritics only strips accents from Latin, Greek and Cyrillic letters, so Hindi, Thai, Korean and other scripts are left intact, and Title Case handles accented and decomposed text and ß correctly. A cell can also be set to a new UUID, the current timestamp, or a server-side function (server date, server UUID, current user) spelled correctly for each engine. These are offered only on plain text columns, never on JSON, XML, enum or SET columns. The server functions are withheld on relay connections, where an older bridge can't save them. The grid's find bar gains Replace and Replace All, and every match becomes a staged edit reviewed and saved like any other. Replace only writes to columns that really come from the table, never to an expression column that merely shares a column's name. On very large results, Messages says exactly which loaded rows Replace All covered. Staged changes can be copied as a SQL script from the pending-changes bar, the preview tab, the confirm dialog, or the command palette. Where the engine allows, the copied script checks that each UPDATE and DELETE changed exactly one row, and its header says how it differs from a save. Staged edits spanning several rows now each record their own original values and rowversion. Before this, saving such edits could fail the concurrency check or report false conflicts.

## Open results in your spreadsheet app

Open in Spreadsheet (in the grid menu and the Export menu) writes the selection, or the whole result, to a private temporary file in the background and opens it in Excel, Numbers, or LibreOffice. CSV files carry a byte-order mark so Excel reads non-English text correctly.

## Edit table and column descriptions, and script the relationship diagram as CREATE

Edit Structure and the table and view properties can now edit descriptions (comments). They are written back with each engine's own statements: SQL Server extended properties, `COMMENT ON` for PostgreSQL, Oracle and DuckDB, ClickHouse `COMMENT`, and MySQL column and table `COMMENT`. On MySQL and MariaDB, a description change made together with a type, default, nullability or name change goes into the same column statement, so neither change undoes the other, and renamed or retyped columns keep their description. Descriptions that can't be read are shown as unavailable instead of being treated as empty. SQLite, libSQL, and views on MySQL and CockroachDB explain why descriptions aren't supported there. The relationship diagram gains Script as CREATE, which writes the tables in view as one script in dependency order, in a new tab on the diagram's own connection. MySQL replays the server's own table definition. PostgreSQL keeps array, enum, domain and generated columns. SQL Server keeps identity seeds and computed columns, and Oracle keeps NUMBER and RAW sizes. CHECK constraints are included. Foreign keys that form a cycle are added with `ALTER TABLE` after all the tables exist, and references the script can't satisfy are listed as warnings.

## Explorer power tools: custom actions, multi-select bulk operations, and a deploy cart

Your own templates can appear in the explorer's right-click menu under Custom Actions. They fill `{server}`, `{database}`, `{schema}` and `{object}` from the object you clicked as properly quoted names, with `{name:literal}` and `{name:raw}` forms for use inside strings. A run-mode action runs straight away only when its SQL is read-only; anything else is shown for review first. Ctrl/Cmd-click and Shift-click select several tables and views, and a banner offers Script CREATE, Script DROP, Export data (which ticks exactly the selected tables), and Maintenance for all of them at once. The selection drops objects that disappear on refresh or disconnect. The new Deploy Cart collects tables (optionally with data), views and routines from any connection. It generates one script, or one file per object in its own `<connection>-<database>` folder. Views and routines come after what they reference, and otherwise keep your order. The script opens on another connection of the same engine for review, and table data is capped at 8 MB while it streams. Clearing or deleting a cart asks first.

## Server variables browser and Open in Terminal

A server's Properties dialog gains a Status page of live status counters next to Configuration, with a search box on both. Settings the server can change at runtime can be edited through a reviewed SQL preview: `sp_configure` (turning on advanced options for the change when needed), `ALTER SYSTEM`, `SET GLOBAL`/`SET PERSIST`, or `SET CLUSTER SETTING`, with a Reset to default option. Startup-only settings are read-only, and editing is refused, with the reason shown, on SELECT-only, rollback-wrapped and locked production connections. Open in Terminal (server right-click menu or command palette) launches psql, mysql, sqlcmd, redis-cli, duckdb, clickhouse-client or SQL*Plus in a terminal window with the connection filled in, including TLS certificates and the real host name through SSH tunnels. The password is passed through the environment, never on the command line, and the window stays open after the client exits. ClickHouse connects on its native port. Relay connections, and DuckDB files SQLLY itself has open, are refused with an explanation. On macOS, Terminal.app can't receive environment variables, so a saved password goes into a launcher script that only you can read and that deletes itself as it runs. The first launch explains this and lets you cancel, and a "Don't show this again" checkbox skips the note after that. It can be turned back on in Settings › Advanced › Database tools.

## Scheduled native backups and query exports, import profiles, and Copy CLI command

The dump scheduler can now run native backups (pg_dump/mysqldump) and saved-query exports to CSV or JSON Lines, not just built-in SQL dumps. It still runs only while SQLLY is open. Each schedule writes into an output folder it creates when needed, names its files with its own id, and prunes only files it created. Query exports follow a moved SQL library, include every row of large results, and refuse multi-result queries. Native backups aren't offered on relay connections. The import wizard can save its column mapping and options as a named profile for each table. A default profile applies when you pick or type its table, or when a dated file or pasted data matches it; profiles are listed with their table. The export, dump, backup, restore, and schedule dialogs gain Copy CLI command, which copies a working `sqlly-cli` command (with its full path) for cron or a runbook, and is disabled where the CLI can't do the job. In the CLI, `--timeout 0` now means no limit, `--format tsv` is supported, `sqlly-cli query` streams CSV, TSV and JSON Lines exports of any size, and SQL that starts with a comment is accepted.

## AI fix replaces the failing statement, a Git panel for the SQL library, and moving tabs between windows

When "Explain Last Error" suggests a fix, Replace failing statement swaps the broken statement for the fix as one undoable edit. It always targets the error the conversation was about, in the tab that failed, and stops if that tab has run again since. The prompt asks for just the failing statement; if the answer rewrites the whole script, the whole run is replaced instead of duplicated. The SQL library panel gains a Git section: a status list, a diff preview, commit with a message, and initializing a repository. It says plainly when git isn't installed. An open project folder gets the same panel from the Git… button in the project file dialog or the palette command Project Folder: Git Changes…. It only covers that folder, and deleted files are committed correctly even when the folder sits inside a larger repository. A query tab's right-click menu, and the palette command Move Tab to New Window, move a tab to another window. The tab keeps its text, connection, file, unsaved history, auto-refresh and file-change tracking, and its results come across as a read-only snapshot (up to 100,000 rows of a large result). Saved charts can be pinned to a connection's Server Dashboard as widgets, each with its own refresh interval, and they run against their chart's own database.

## Redis tools: profiler, Pub/Sub viewer, memory analyzer, bulk actions, value formats, and slow-log threshold

The Activity Monitor gains a Redis Profiler, a MONITOR capture on its own connection with a cap, pause, filters and a time limit. It also gains a Pub/Sub viewer for channels and patterns; a leading `=` subscribes to a channel literally, and binary channel names show as escapes. Both are also on the Redis database's right-click menu, and both work on Redis-compatible servers (Valkey, KeyDB, Dragonfly, ElastiCache, MemoryDB). They stop as soon as their connection is disconnected or deleted, are refused on relay connections, and keep your selection and scroll position while data streams in. The query editor still refuses MONITOR and SUBSCRIBE and points to these tools. The Memory Analyzer opens a report pane beside Disk Usage, from the database's right-click menu, a command, or the Server Dashboard. It shows memory by data type, the largest keys, and a TTL histogram from a single sample of keys, and says whether its figures are exact or extrapolated. When MEMORY USAGE is unavailable or denied, it still shows the type and TTL reports. Keys can be deleted or have their TTL set or cleared by pattern or folder, always after a dry-run count; bulk delete asks you to type the count. A command file can be imported with errors reported per line; a failing line no longer stops the rest. Destructive and admin commands in the file are listed for review and need a typed confirmation. All write actions respect read-only and locked production connections. The value viewer has a format picker (Auto, UTF-8, JSON, Hex, MessagePack) that remembers your choice for each key you reopen during the session. Malformed or hostile MessagePack can no longer crash the app, and MessagePack timestamps are decoded. The slow-log tab shows the current threshold (any negative value reads as disabled), explains why it can't be read, and changes it through a reviewed `CONFIG SET` that respects the production lock.

## Fixes to existing tools found while hardening this batch

Admin panes that act on the selected grid row (Query Store, SQL Agent, Activity Monitor, Index Analyzer, Extended Events, Schema Compare, Schema History and database search) now act on the row you highlighted even after sorting the grid. Before, a sorted grid could run, kill or script a different row. On very large results, View Full Value, Cell Details, and the grid's edit, paste and row actions now use the row you're looking at after scrolling, not a row near the top of the result. Exporting or copying a grid whose filter hides every row now exports nothing instead of the whole result. Table and scheduled exports no longer stop silently at the point where a large result spills to disk. With several windows open, saving the session keeps every window's tabs instead of each window overwriting the others. App settings files are written atomically and readable only by you.
## Relay bridges report what they support, and staged saves work over relays

A relay bridge now tells SQLLY which features it supports when a session opens, and older bridges keep working. Staged grid edits can be saved over relay connections in one transaction that rolls back if a row changed underneath. Server date, server UUID and current user are offered when the bridge can run them, and FK labels work over relays. With an updated bridge, the grid gets 8 KiB previews of very long values that open in full on demand, while exports still write every value whole. With an older bridge, the pending-changes bar says the bridge needs updating instead of letting a save fail.

## Data Compare, Schema Compare and SQL Server scripts

Data Compare no longer crashes SQLLY when you press Compare. It also finishes when you type the key columns yourself, and finds the primary key on SQLite, MySQL and Oracle tables. Schema Compare, and the login-to-database-user mapping in Security, no longer fail with a collation-conflict error on SQL Server. Edit Structure on SQL Server keeps a column's collation when you change its type. Changing a column's type together with its default, or renaming and retyping a column that has a default, now produces a script that runs. Script as CREATE keeps index key columns (they were being written as INCLUDE columns), SQL Server collations, filegroups and table and index compression, and Oracle CHAR/BYTE lengths and INTEGER columns. It warns about temporal, partitioned, memory-optimized and columnstore tables it copies as ordinary tables.

## Keyboard multi-select, template parameters, and FK names in value autocomplete

The Object Explorer's bulk selection works from the keyboard: Shift+arrows extend it, Space toggles a row, and Esc clears. Custom explorer actions whose templates have parameters ask for the values first. Deploy Cart file exports are numbered in the same dependency order as its script, and table export always uses the dialog's own connection. Value autocomplete on a foreign-key column lists the referenced names (for example category names) and inserts the id. Query-parameter values move with a tab to another window and come back when SQLLY relaunches. Quoted names containing an escaped quote character are read as their real names.

## Terminal, Redis and scheduling refinements

ClickHouse connections gain an optional Native port for Open in Terminal. Tunneled ClickHouse connections get a second tunnel to the native port, kept until the connection is disconnected. sqlcmd gets the encryption and host-name switches its installed version supports. Redis Pub/Sub and Profiler captures keep at most 64 KiB per message within a 64 MB budget and mark truncated payloads. Redis value formats are remembered across restarts. The Scheduled dumps pane no longer re-reads its file on every repaint, and custom explorer actions no longer read the template file each time the menu opens.

## Grid filters stay on the right column, and exports write long values in full

Filters, column formats, copies, saved column layouts and every right-click action now stay on the right column while edits are staged. Before, the pending-changes marker column could shift them one column over. On very large results, Top Values, Copy Distinct, copying, exporting, snapshots, profiling, transposing and moving a tab read from disk in the background with a note above the grid, instead of freezing the app. Table, scheduled, CLI, database-dump and data-transfer exports now write cells over 8 KiB in full, and grid exports say when they contain shortened previews. Saved column layouts are written safely and are never overwritten when the file can't be read. The Ctrl+Tab switcher's rows no longer overlap, and each row shows its own tab's connection.

## Canvas results layout fills the pane and flags mistakes in the editor

The Canvas results layout now fills the results pane with equal cells at any window size, honoring row and column spans, instead of drawing small boxes pushed to the right edge. Layout mistakes are now underlined in the editor on the line at fault: a malformed, overlapping or off-board placement, a placement with no query after it, more queries than cells, or an oversized board. A result set that only turns out to have no cell when the query runs is listed under the board. A board larger than 8x8 is ignored and the results are shown stacked.

## Grid menu actions no longer crash, and hidden dialogs now open

Filter Rows… and most other result-grid right-click actions (sorting, the row form and editors, snapshots, charts, profiling, layouts, FK labels) could crash the app; they now run safely, and Transpose is back in the grid menu. The filter builder and the snapshot prompt open on top of the results instead of behind them. Edit Structure, MCP Activity and Tunnel Profiles now open as proper dialogs instead of never appearing. The SQL Library's Git Diff preview opens centered on the window instead of cut off inside the sidebar. The Redis Memory Analyzer grids and the Server Dashboard's database sizes now show their rows. Whole numbers in tool grids no longer show ".00". The macOS Open in Terminal notice and long server names in connection confirmations wrap instead of running off the dialog.

## Tunnel profile deletion asks first and cleans up saved passwords

Deleting a tunnel profile now asks first, names every saved connection that will lose its tunnel, and removes the profile's saved passwords from the keychain. On macOS the status bar no longer says "Opening a terminal…" while the Open in Terminal notice is waiting; it clears when you cancel and says "Opened a terminal for …" once the terminal starts.
