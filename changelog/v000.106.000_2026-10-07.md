# 2026-10-07

## Update dialog: real buttons and a visible download link

In the update dialog, "Skip this version", "Remind me later" and "Download when idle" now look like buttons, with a border and fill matching Close and Check Again Now. Before, they were plain text that was easy to miss. The dialog also shows a "Download:" link to the sqlly.app download page, next to the per-platform Download button, so you can pick any platform or package. The dialog is wider, so every button fits on one row. If the buttons still don't fit, they now wrap to a second row instead of running off the edge. Every dialog gets this wrapping.

## Mac App Store Lifetime License is now $69.99

The one-time "SQLLY Lifetime License" in-app purchase in the Mac App Store edition now costs $69.99 instead of $150. It unlocks SQLLY on your Macs only. The $200 Lifetime license on sqlly.app still covers every platform. The Unlock SQLLY dialog shows the new price.

## Mac App Store edition keeps its own keychain entries

The Mac App Store edition now saves passwords, AI provider keys, MCP and agent environment secrets, your SQLly sign-in, and the relay device key under keychain names of its own (each ends in `.mac-app-store`). With both editions on one Mac, they used to look up the same keychain entries. Because the two are signed differently, macOS stopped to ask for your Mac password whenever one edition read an entry the other had saved. Now neither edition ever reads the other's entries, so neither asks. The direct download keeps its existing names, so nothing it has already saved is lost. To move connections and their passwords between editions, use File ▸ Export Credentials in one and File ▸ Import Connections in the other. Help ▸ Mac App Store Edition now explains this step by step.

## Protections set on the Dev environment now apply to DEV connections

Safety options ticked on the built-in Dev environment, such as "Block all but SELECT", were silently ignored for connections marked DEV, and didn't show as inherited in the connection editor. The app looked the environment up as "Development", but the built-in one is named "Dev". DEV connections now pick up the Dev environment's protections, along with the MCP server's read-only checks and credential exports. An environment named "Development", from older files, is still recognized.

## Results formatting settings now reach the grid

Several Results formatting settings used to change only the preview in Settings; now they change the results grid too. Unique ID "Show dashes" and alignment apply to UUID columns, and copies and exports still keep the dashes. Decimal columns use your chosen decimal separator and thousands character (for example 1.234.567,89 or 1'234'567.89), and "Reduce large numbers" now abbreviates both integer and decimal cells (1.50K, 2.34M). Sorting and number filters still use the exact values. The Settings preview now uses the grid's own formatter, so the two always match. One change: the "Reduce large numbers" threshold now only decides which values get shortened, and the units are always thousands, so with a threshold of 10000, 15000 shows as 15.00K instead of 1.50K. The default threshold of 1000 looks the same as before.

## Date formatting directives work, and table.column overrides match

The `date=` formatting directive, and the Date choices in "Set Formatting Override…", now actually reformat date and time columns. Before, they had no visible effect. Values keep their time zone handling, date-only values are never shifted, and a pattern the grid can't use leaves the value as it was. Column overrides written as `table.column` (or `schema.table.column`) now match when SQLly knows which table a result column came from, and they win over a plain column-name override. Before, only bare column names ever matched.

## Masked columns stay masked when copied or exported

A `mask=` formatting directive used to hide values in the grid, but copying or exporting the result still produced the real values. Directive masks now follow the same "Apply mask formatting to copies and exports" setting as Column-override masks, and they count as masked for the toolbar indicator and AI sampling.

## SQL formatter keeps GO on its own line

Formatting a T-SQL script with `GO` batch separators used to glue `GO` onto the end of the previous line, and short scripts collapsed into a single line. `GO` (including `GO 5` and a trailing comment) now stays on its own line, separates statements, and is never folded into a one-line statement. A column or string named "go" is left alone. With the dialect on Auto Detect, a script with `GO` lines is now formatted as SQL Server.

## Auto-alias never suggests a SQL keyword

Automatic table aliases could produce a reserved word, for example `or` for a table named `orders`, which broke the query. Every alias style now skips keywords and numbers the alias instead (`or1`), and the keyword list now covers more words, such as `of`, `for`, `and`, `with` and `from`.

## JOIN suggestions for multi-column foreign keys

When a foreign key spans several columns, JOIN completion used to offer a separate suggestion for each column pair. It now offers one suggestion that joins every pair with AND, in key order. Separate foreign keys to the same table are still offered separately.
