# 2026-10-18

## Browser sessions through a bridge reconnect on their own

When SQLly in the browser loses its session with a bridge (the bridge restarted, the network blipped), it now says why, using the bridge's own words, and reconnects on its own with a short backoff instead of asking for a reload. A refusal (expired launch, seat or session limit, license not ok) is shown verbatim and ends the retries, instead of a generic "could not reach the relay proxy".

## Server Explorer retries a failed server when you connect to it

Expanding a server whose first database listing failed left a tiny red dot and no children, and picking the server in the query bar did not retry it: the one database that then appeared came from IntelliSense, and only Refresh re-ran the listing. Connecting to a server (query bar, sidebar, command palette) now retries a failed listing, and the status line names the reason a listing failed instead of just "Could not connect".
