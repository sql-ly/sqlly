# 2026-10-22

## SSH connections no longer time out while the host-key dialog is open

When connecting to a new SSH host, the time spent reading the fingerprint and clicking Trust no longer counts toward the connection timeout. Before, taking more than about thirty seconds to answer made the connection fail with "timed out" even after it was trusted, and the second try worked. A server that really is unresponsive still fails after the usual timeout.

## Filter menu fixes on binary, long and timestamp values

"Add WHERE … IS NULL" and "IS NOT NULL" now work on cut-down previews and binary placeholders; they did nothing before. Equality filters on MySQL and PostgreSQL timestamp columns build again (they were mistaken for SQL Server rowversion bytes). "Match row" reads a spilled row from disk once instead of once per column. SQL Server rowversion and timestamp columns are now treated as binary everywhere: in the grid, in the filter menu and in the row editor.

## Column checks stay on for MySQL queries that mention dual

A query with `FROM dual` switched off the as-you-type check for unknown column names. It no longer does.

## A keepalive failure no longer blocks SQL Server connections

If the system refuses to turn on TCP keepalive for a SQL Server connection, the connection now goes ahead and the refusal is logged, matching PostgreSQL and MySQL.
## The filter menu only offers filters it can build

Every "Add WHERE" item on the results grid's right-click menu is now checked against the same code that runs when you click it, and an item that could not build is left off the menu instead of doing nothing when clicked. A cell cut short to a preview is always marked as cut, so it never offers a filter on the preview. On SQLite, where any column can hold binary data, the text filters ("contains", "starts with", "ends with") now work on binary values too, matching what SQLite's LIKE does. An empty binary value shown as "0x" now filters as the empty value.

## Restored results keep the engine they ran on

Results restored from query history, from the results cache, or carried along when a tab moves to another window are now read as the database they actually came from, even if the tab has since been connected somewhere else. Before, a SQL Server timestamp column restored into a tab now connected to PostgreSQL was shown and filtered as a date. History versions saved before this change are read without assuming any engine.

## Updated the async runtime

Updated the async runtime to fix a timer race reported in RUSTSEC-2026-0384.

## One connection file for exporting with or without passwords

Export Connections and Export Conn w/ Creds (renamed from Export Credentials) now write the same file and open the same picker, so you choose exactly which servers and databases to include either way. Only Export Conn w/ Creds puts passwords in the file, and its dialog now opens with a warning at the top that the file will contain them in clear text and that anyone with the file can sign in. An SSH tunnel that signs in with a password keeps that sign-in method in a file without the password. Import Connections is the one import for both kinds of file and for files saved by earlier versions; it says how many passwords went into your keychain and asks for the rest on first connect.

Either export always includes your clients, projects, environments and shared logins, whichever connections you pick, as the old Export Connections did. A shared login's password is included only when a picked connection uses it, and only with Export Conn w/ Creds. A store with labels but no connections can be exported too.

## Imported connections show up right away

Connections added with Import Connections, Import From Other Tools, or a Redis Insight import now appear in the server explorer as soon as the import finishes, instead of only after restarting SQLLY.

## The account window opens without a pause on Windows

Opening the account or sign-in window no longer waits on two helper programs and two Credential Manager reads before it appears. The window opens at once and checks your account in the background, and the device name and ID are read directly from the registry. Returning to the app no longer reads the keychain on the main thread either.

## The server explorer is visible on first launch on Windows

On a fresh Windows install the server explorer could open squeezed to nothing, because the first frame of a new window is laid out before its real size arrives. The explorer and the AI panel now keep their width.

## Keywords in IntelliSense are not highlighted

Keyword suggestions in the completion list are now plain text. Tables, columns, functions and other names still highlight the letters you typed.

## Shorter right-click menus, and New Query first on databases

Right-clicking a database now always starts with New Query, on every engine. The explorer's longest menus keep their everyday actions at the top and group the rest into the same submenus everywhere: Script As, Data, Schema, Dependencies, AI, Tools, Delete and Copy, plus Connection on servers and Bulk Edit, Import / Export, Expiry and Copy To on Redis. A table's menu goes from 29 entries to 17, and a database's tool windows are sorted into Data, Schema and Tools. The SQL editor's right-click menu groups its commands into Edit, Find, Format, Folding and Automagic submenus, with the contextual fixes still first. Nothing was removed.
