# 2026-11-12

## Large results in the browser stay in browser storage, not memory

The browser version (the in-tab preview and SQLly Embedded pages) now handles big results the way the desktop app does. Past the spill threshold (50,000 rows or 64 MB by default, under Settings › Performance › Query Result Optimizations) the rest of the result goes to the browser's Origin Private File System through a small background worker, and the grid pages from there as you scroll, so a multi-million-row result no longer has to fit in the tab's memory. Scrolling, View Row as Form, copy and export (first 100,000 rows), Top Values, profiling, Pivot and Chart over every row, and pivot drill-through all work on these results. The stored rows are deleted when the result is replaced, and any a closed tab left behind are removed the next time SQLly opens in that browser. A browser without that storage, or with under about 64 MB free, keeps results in memory as before and says so in Messages; if storage fills up partway, the rows already stored are kept and Messages says how many. SQLite results in the preview are now read in batches as they are moved to storage, instead of being held in full first.
