# 2026-09-28

## Sample IntelliSense report uses read-only boxes

On the sample IntelliSense feedback report, the description and both sets of test instructions now appear in read-only text boxes, the same fields the report form uses.

## Security dialog redesign, with working password fields

The Security dialog (logins, users, roles and accounts) has been rebuilt to be much easier to work with. Password fields now accept typing: before, clicking into one handed keyboard focus straight back to the dialog, and fields that did take text never refreshed the Apply button. On SQL Server, creating or editing a database user now handles passwords: a new user can map to an existing login, create a new SQL login with a password in the same step, be a contained user with its own password, or have no login. Editing a user resets the password where it actually lives (the contained user or its SQL login), and the dialog says which. Every password section has a Generate button that fills in a strong password and copies it to the clipboard, plus a live strength meter and a check that both entries match.

The generated SQL now sits in a read-only, selectable text area that updates as you edit, with a Copy All button. Passwords are masked on screen unless you tick Show passwords, but Copy All always copies runnable SQL. Problems that block Apply appear as a list above the SQL instead of silently disabling the button. Other improvements: the principal list has a filter box and kind/disabled tags, tabs show counts, checklists show "n of m" with All/None, you can revert unsaved edits, ⌘↩ applies, and there is a Drop action with a review-then-confirm step (dropping a SQL Server login also removes its mapped database users). MySQL accounts gain a database picker for database-level privileges.

Fixed along the way: loading a login's details no longer fails with a collation-conflict error (Msg 451) when the server's databases use different collations; the Users tab loads its users when first opened; PostgreSQL roles no longer propose unwanted ALTER ROLE changes from mismatched attribute defaults, and all role attributes are now editable; a password typed for one principal no longer carries over when you select another; and the "Applied" confirmation is no longer overwritten by the reload that follows it.
