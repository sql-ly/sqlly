# 2026-10-19

## Redis key view with per-type editing

Opening a Redis key from the explorer now shows a key view instead of a bare query result: a header strip with the key's type, TTL, encoding, memory and length, the value loaded in pages with a "showing N of M" count and a Load more button (long strings in 1 MB windows), and the selected value under the grid with the Auto / UTF-8 / JSON / Hex / MessagePack picker. Each type offers the edits it allows — set a string while keeping its expiry, add, edit and delete hash fields, set, push and remove list elements, add and remove set members, add, re-score and remove sorted-set members, replace a JSON document — and every edit shows the exact command before it runs, is refused on read-only and locked production connections, and asks for a confirming click wherever a query tab would confirm. Values travel as bytes the whole way, so a value such as 00014 is never turned into a number; binary values are shown and edited as hex. Open in Query Tab on a key's menu keeps the earlier reader-in-a-tab behaviour, and Redis Key View… in the command palette opens the view with a key-name prompt.

## Redis command IntelliSense

Redis query tabs now complete as they should: command names as you type, the options that fit after a command (and only those that still can be combined), the subcommands of container commands, and key names drawn from what the Server Explorer has already scanned for the tab's database. Hovering a command shows its documented syntax, summary and complexity with a Write, Destructive or Blocking badge, and signature help tracks the argument you are on. The vocabulary comes from the connected server's own command documentation, so Redis Stack modules and server-specific commands complete too, with a bundled Redis 7.4 snapshot as the fallback for servers that refuse or predate it. The command-line IntelliSense tool accepts Redis scripts as well.

## Redis Stack module replies come back as tables

Search results now show one row per document with a column per field, aggregations one row per group, time-series ranges a readable timestamp beside each value, and the JSON, Bloom, cuckoo, top-k, count-min, geo, stream-info, and latency commands each get the columns their replies imply. The shapes are the same whether the server answers in the classic reply protocol or the newer one, and a time-series range opened from the key browser lands on the Chart tab with the timestamp on the horizontal axis.

## Search indexes in the Redis explorer

Redis databases on a server with the search module gain an Indexes folder listing each index with its document count, key type, and prefixes. An index opens to its definition, and its menu offers Query…, Explain…, Profile…, and a reviewed Drop Index…. Servers without the module show nothing extra.

## Value viewer decodes compressed, encoded, and serialized values

The value viewer's format menu gains gzip, zstd, LZ4, deflate, Base64, Protobuf, PHP, Java, and Python pickle alongside Auto, UTF-8, JSON, Hex, and MessagePack. Compressed values are decompressed and then shown as whatever they contain, so a gzip-wrapped JSON document opens as a JSON tree; Base64 is decoded the same way; a Protobuf message is dumped by field number and value without a schema; PHP serializations decode to readable JSON; Java and Python pickle payloads are recognised and summarised by the class names, opcodes, and strings they carry. Auto mode now recognises all of these by their leading bytes and says what it found. Every decoder treats the value as untrusted: decompressed output is capped at 16 MB, nesting at 128 levels, and a payload that claims more than that, or is truncated, is reported honestly instead of exhausting memory. The bytes of the value are never changed by any choice; formats are presentation only. Remembered per-key formats are now stored with a version, and a format name a newer SQLly wrote that this one does not know falls back to Auto instead of refusing to load the file. The Pub/Sub viewer's Preview Payload uses the same menu.

## Key events in the Redis Pub/Sub viewer

The Pub/Sub tab gained a Key events button that subscribes to every keyspace notification on the connection's logical database, with a key pattern typed first also watched by name. Notifications now fill dedicated event and key columns (an expired `user:42` reads as `expired` / `user:42`) while ordinary messages leave them empty. Because a stock server has notifications off, the tab reads the server's notification setting when it opens, says what it found, and offers Enable Key Events (KEA)… — a reviewed change shown in the same confirm-before-run strip as the slow-log threshold, honouring the production write lock.

## The Redis key browser says exactly how much of a listing you are seeing

A long Redis listing used to stop quietly: the walk ended at 10,000 keys with a one-line note, and nothing said how many of the scanned rows were actually drawn. One note row now covers both cuts — what is shown of what was scanned, and whether the scan itself stopped — and offers the way on: click it to load more of the rows already scanned without another round trip, or choose Scan more (on the note, the database, or a folder) to continue the same scan from where it stopped, with the new keys folded into the rows already on screen. Database rows show how many keys carry an expiry beside their key count.

## Redis bulk counts and memory samples can be stopped, and partial counts say so

Counting the keys a bulk delete or bulk expiry would touch now runs a page at a time with a running total and a Stop button; a count that was stopped or hit its cap is labelled partial, and the action still touches only the keys it listed. Delete and expiry batches shrink whenever one takes longer than a second, so a Stop never waits long for the batch in flight. The memory analyzer gained a Stop that cancels the sample on the server and keeps the previous reports on screen.

## Redis expiry and filter actions use one wording everywhere

Remove TTL (Persist), the Remove TTL dialog, and its Persist button are all "Remove expiry (PERSIST)" now, in the key menu and the bulk expiry dialog; Show All Keys is "Clear Key Filter". Opening a list, sorted set, or stream names its tab "first 1,000" so a capped read is never mistaken for the whole value.

## Redis key filters are remembered per database and the last five patterns are one click away

The pattern you filter a Redis database with is remembered for that database on that connection and is back in force the next time you open the app, and the Filter Keys… dialog offers the last five patterns you typed on the connection in a Recent dropdown. Filters live beside your connection list, never in the connection itself, so sharing or exporting a connection never carries them.

## Redis values are proven byte-exact on every read path

A live test suite now pushes the values a numeric coercion would mangle — a number with leading zeros, the empty string, a NUL byte, invalid UTF-8, a 40-digit integer, a float that overflows, and 100 KB and 2 MB strings — through the command editor, the key browser, a hash read, and the Pub/Sub viewer, and checks that exactly the same bytes come back as text in the grid, never as a number. The same suite covers the three TLS modes against a TLS-only server, and a scale check times the key browser, memory analyzer, and bulk dry run on a one-million-key database. Typed exports (CSV, JSON, Excel, SQL scripts) are checked to write such values as text as well.

## Redis Sentinel connections

Redis and Valkey connections can now go through Sentinel: name the master and list the sentinels (plus a sentinel password when they need one) and SQLLY asks the sentinels for the current master on every connect, with Test Connection showing which master and which sentinel answered. Pasting a `redis+sentinel://` URL fills the same fields, and a comma-separated host list in any Redis URL is kept whole instead of dropping everything after the first host. Sentinel connections dial the sentinels and the master directly: SSH tunnels, proxies and relay routes are refused with a message saying so rather than connecting somewhere wrong.

## Read from a replica and survive failovers on Sentinel connections

A new Prefer replica for reads option runs scripts made only of read-only commands on a healthy replica, falling back to the master when none is up. When the master changes underneath an open session, SQLLY re-asks the sentinels once and retries the read automatically so a read-only script carries on; a script that writes is never re-run and instead stops with "master changed, re-run", so the same write can never land twice.

## Redis streams and consumer groups in the key view

Opening a stream key now shows Entries, Groups, Consumers and Pending tabs: entries page through the stream with Load more, each consumer group shows its consumers, pending count, last delivered entry and lag, and the pending list shows which consumer holds each unacknowledged entry, how many milliseconds it has been idle and how often it was delivered, so a dead consumer stands out. You can append an entry, delete one, acknowledge, claim or auto-claim pending entries for another consumer, create or destroy a group, and trim the stream from the view; each action shows the exact command first, respects read-only and locked production connections and the connection's confirmation setting, and trimming or destroying a group asks you to type the count or the group name before it runs.

## Redis Cluster connections

Redis connections can now reach Redis Cluster, ElastiCache in cluster mode and MemoryDB. List one or more seed hosts in the Server field (commas, or a pasted URL with several hosts), and leave Cluster mode on Detect automatically or set it to Redis Cluster; every command then goes to the node that owns its key's slot, slot moves after a failover or reshard are followed automatically, and a script that saw redirects says how many in the Messages pane. Commands a cluster cannot run as typed — multi-key commands whose keys are in different slots, SELECT of a database other than 0, KEYS, SCAN and MULTI/EXEC — are refused before they are sent with a message naming the rule (for multi-key commands: give the keys a common {hash tag}). Single-server connections behave exactly as before apart from one INFO cluster probe on the first connect of a session.

## Cluster node map and per-node SSH forwards

When cluster nodes announce addresses this machine cannot dial — behind NAT, a Docker port mapping or an SSH bastion — the new Cluster node map field rewrites each announced address into the one to dial (one "announced => dial" pair per line), while the announced address keeps naming the node for redirects and TLS. Connections through SSH hops or a SOCKS/HTTP proxy now open a separate forward for every node the cluster names, so nodes that only the bastion can reach work too.

## Cluster Topology view with a per-node connection trace

A new Cluster Topology view (database right-click menu, the command palette, or the Server Dashboard of a cluster connection) lists every node from CLUSTER SHARDS, or CLUSTER NODES on servers before 7.0: role, slots, health, replication offset, link state, the announced address and hostname, the address SQLLY dials, and the TLS name it sends. The footer checks that all 16,384 slots are covered and names unhealthy or remapped nodes, and Trace runs the same step-by-step check as Test Connection against each node — name lookup, tunnel or proxy with the node map, TCP, TLS checked against the address the node announces, sign-in, protocol and ping, database, and cluster state — one row each, so the first failing row says what to fix.

## Key browser, memory analyzer, bulk actions and live tools across every master

On a cluster the key browser walks every master in turn (its note says how many keys it scanned across how many masters, and Scan more continues on the node where it stopped), the memory analyzer splits its sample across masters in proportion to their key counts, bulk delete groups keys by hash slot so every UNLINK batch stays inside one slot, the Profiler runs MONITOR on every master with a node column, and the Pub/Sub viewer subscribes keyspace notifications on every master, ordinary channels once, and sharded channels on the master that owns them, again with a node column.

## Sharded Pub/Sub channels in the viewer

The Pub/Sub viewer now subscribes to sharded channels: enter one with a leading # (for example #orders) and it is watched with SSUBSCRIBE, on a cluster at the master that owns the channel and on a standalone Redis 7 server directly. Typing SSUBSCRIBE in a query tab now points to the viewer instead of to redis-cli.

## Redis Test Connection shows every step

Testing a Redis connection now reports each step as it happens — name lookup, tunnel or proxy, TCP, TLS (version, cipher, server name, certificates presented and whether they verify), sign-in, protocol and ping, logical database, and whether the endpoint is a cluster node — in the diagnostic log, and the error you see is headed by the step that failed (for example "TLS failed: the certificate does not verify against the bundled public roots") instead of a generic connection error. A wrong logical database on a cluster now says a cluster has only database 0.

## Redis connections use RESP3 when the server offers it

Redis query connections ask for the RESP3 protocol and quietly fall back to RESP2 on servers that do not have it. Results look exactly the same on both protocols: hashes, configuration listings, scored ranges and scores are shown in the same rows and spellings. The server details from Test Connection now say which protocol the connection uses and whether it is encrypted.

## Every SQLly Redis connection has a name

Query connections, the Profiler's monitor connection, and the Pub/Sub viewer's connection name themselves after your saved connection and the app process, so they are easy to find in the server's client list and in the Activity Monitor's Sessions tab. A server that refuses the naming command simply leaves them unnamed; on servers without RESP3 the Pub/Sub viewer's connection cannot be named.

## Redis command timeout

A Redis command that gets no reply within the connection's query timeout — 30 seconds when none is set, no limit when it is 0 — now fails with a message naming the command and the limit, instead of leaving the tab waiting on a stuck server or a half-dead network path. Blocking commands get their own wait on top, and nothing is ever re-run automatically. The Profiler and Pub/Sub viewer keep waiting without a limit.

## SSH tunnels stay alive and reopen after a drop

SSH tunnels now send a keepalive after 30 seconds of silence (configurable per connection with the new Keepalive (seconds) field; 0 turns it off), so idle tunnels survive firewall and NAT timeouts. When a tunnel's SSH session ends anyway, SQLly notices and opens a fresh tunnel for the next connection instead of handing out a dead port; a Redis run that needed the new tunnel says "Tunnel re-established" in its messages. Commands are never re-run on your behalf. The keepalive settings travel with exported connections and credential files.

## Redis TLS can trust your computer's certificate store

A Redis connection in Verify CA or Verify full can now also trust the operating system's certificate store (the macOS keychain, the Windows certificate store, or the Linux CA bundle), so a company CA installed on your machine verifies without pointing the connection at a CA file. Pasting a `rediss://` URL turns TLS on as Require and no longer lowers a connection that already verifies certificates.

## A Redis CA file adds to the built-in certificate authorities

A CA file on a Redis connection is now trusted alongside the public certificate authorities built into SQLly, as it already was for PostgreSQL, instead of replacing them, so adding your private CA no longer stops servers with public certificates from verifying.

## Verify full through an SSH tunnel checks the right name

A Redis connection in Verify full that goes through an SSH tunnel or proxy now checks the server's certificate against the server name on the connection rather than the tunnel's local address, so a correctly issued certificate verifies through the tunnel. Test Connection's TLS step checks the same name.

## Cluster Trace and Sentinel use the full connection test

The Cluster Topology view's Trace now runs the same step-by-step connection test as Test Connection against every node, checking each node's certificate against the address it announces, and Test Connection on a Sentinel connection traces the master the sentinels name. Cluster node connections, Sentinel master and replica connections now also use RESP3 when offered, name themselves, and get the command timeout.

## Microsoft Entra sign-in for Azure Cache for Redis and Azure Managed Redis

Redis connections can now sign in with Microsoft Entra: SQLLY gets a token for Azure's Redis service from the same signed-in Azure account your Azure SQL connections use, signs in as that identity's object id, and signs an open connection in again with a fresh token before the old one expires. The connection editor offers Microsoft Entra for Redis connections, explains what the cache needs, and warns when the host is not an Azure Redis endpoint. Verified against a scripted sign-in and a local Redis standing in for the cache; not yet run against a live Azure instance.

## Rename and copy Redis keys, and export folders as command files

A key's menu in the explorer now offers Rename… (refusing to overwrite unless you allow it), Copy to Database… and Copy to Connection…, each showing the exact command first and respecting read-only and production locks on both ends. Folders and databases gain Export as Command File…, which writes the matching keys — strings, hashes, lists, sets, sorted sets, streams and JSON documents, with their expiry — to a file Import Command File… runs back; binary values are written as escapes, so the round trip is byte-exact, and the file says whether the export was complete.

## Redis ACL page in the Security tool

On Redis connections the Security tool now opens an ACL page listing every user with its enabled state, password count, key, channel and command rules and selectors, plus the server's recent access denials. Add, Edit and Delete script a reviewed user definition into a query tab rather than changing anything directly, and new passwords are written as hashes so the clear text never lands in the tab or history. ElastiCache and MemoryDB, whose users AWS manages, explain why the page is not offered.

## Names for Redis logical databases

Right-click a Redis database and choose Rename… to name it — the explorer shows db3 — sessions, and the key view, key dialogs and bulk-action summaries use the name — or Show Only Databases… to list just the databases you use, in your order. Both are kept on your computer with the connection and never change the server.

## Import connections from Redis Insight

Import From Other Tools now reads Redis Insight database exports, plain or base64. Each database becomes a Redis connection with its host, port, logical database, user, SSH tunnel and TLS settings — TLS is never dropped, certificates are saved as files only you can read, and passwords and passphrases go to your system keychain. Entra-signed Azure databases import with Microsoft Entra sign-in, cluster databases as Redis Cluster connections, and Sentinel databases as Sentinel connections with the master group and the sentinel password.

## Entra sign-in covers Sentinel and Cluster connections

Microsoft Entra sign-in for Redis now keeps every kind of connection signed in: a Sentinel connection's master, the replica that serves reads, and a new master after a failover (which signs in with the newest token, not the one the session started with), and every node of a Redis Cluster connection, whose routed connection is rebuilt with the fresh token so a node that reconnects later signs in with it too.

## Redis user name for Entra sign-in

A Redis connection that signs in with Microsoft Entra can name the Redis user to sign in as, for caches whose access policy names the identity by one; left blank, it signs in as the token's object id as before. The name travels with exported connections and credential files.

## Redis Insight Sentinel and Cluster databases import

Importing a Redis Insight export now brings Sentinel databases over as Sentinel connections — the master group, the sentinel to ask, the sentinel's password (moved to the keychain) and the master's own sign-in — and cluster databases as Redis Cluster connections, or as one node when Redis Insight was set to force standalone. Credential files gained matching fields for the Sentinel password, the cluster mode and node map, and the Entra Redis user name.

## Copy to Database and MOVE on a cluster

On a Redis Cluster connection, Copy to Database… and MOVE are refused with a message saying a cluster has one logical database and pointing to Copy to Connection… instead of failing with the server's error.
